Corrections

Every figure the Cost Index published and got wrong, with the check script that now prevents it. Append-only: entries are added, never edited or removed.

This is not the revisions ledger. Revisions record a public source changing its own number after the fact — someone else's correction. This page records ours.

How this works

A correction here carries five things: what was published, what is true, when it broke, why it broke, and the name of the gate that now makes that specific error fail a build. The last one is the point. A number being wrong is ordinary; what is checkable is whether the machine that produced it got better. Every gate named below is a script in the public repository — clone it and run it.

Some entries are marked pending. That means the gate shipped before the prose was rewritten. Publishing them in that state is deliberate: the record should show what was known on the day it was known, not only after it was tidy.

The machine-readable ledger is at /cost-index/corrections.json, public domain, same terms as the rest of the Index.

COR-004 corrected broke 2026-07-09 · found 2026-08-07
We published
llms.txt and es/llms.txt: 'The Muntin Cost Index publishes weekly wholesale reference prices' / 'publica semanalmente precios mayoristas de referencia'.
What is true
The Index dispatch has been MONTHLY since 2026-07-09. Both files now say monthly / mensualmente.
Why it broke
The cadence changed by decision, and the decision was recorded in the workflow header that is its source of truth — but llms.txt is generated by a builder with the old wording hard-coded, and nothing connected the two. The file written specifically so machines describe the company accurately was the one describing it wrongly, in both languages, for 29 days.
Gate that now prevents it
scripts/check-cost-index-dispatch-fresh.mjs
The assertion was added to the gate that already owns dispatch cadence rather than as a new script — a new gate is a new obligation in a one-person company. It scans both locales. Verified to have teeth by reintroducing the old wording, which turned the gate red and named the line.

COR-003 pending broke 2026-07-06 · found 2026-08-07
We published
A cite drawer in the July 2026 dispatch: "both rebuilt from committed data on every refresh and re-checked in CI. Every number in this section traces to one of them."
What is true
No CI check re-checked those citations. The claim was false when written.
Why it broke
A statement about the company's own machinery was written from intent rather than from the machinery. It is the most serious item on this ledger — a false claim about a gate is worse than a stale number, because it invites a reader to trust everything else on the page.
Gate that now prevents it
scripts/check-src-sentinel.mjs
The claim is now true for the classes this gate covers. It is wired into check-all, which runs inside the Cloudflare deploy, so a false citation blocks a deploy rather than reaching a reader.

COR-002 pending broke 2026-07-07 · found 2026-08-07
We published
The July 2026 dispatch's #the-record section: band pooled coverage 0.772 across 32 items and 4,588 scored steps; direction calls 0.536 over 1,859 scored calls; a revision ledger of 2,080 entries.
What is true
Against the files the post names, those figures now read 0.767, 75 items, 79,086 scored steps, 0.506, 34,029 scored calls, and 10,294 entries.
Why it broke
Static prose cited moving files. Every figure was true on publication day and went false the next time a builder ran. The two annotations in that post that are still true are the two whose value is structural — a verdict and an empty list — which is the whole diagnosis in one line.
Gate that now prevents it
scripts/check-src-sentinel.mjs
New. It resolves every <!-- src: --> citation against the file it names and fails on a false claim, and it defines an anchored grammar — edition:<asOf> <path> = <value> — that resolves against the append-only frozen edition spine instead of a live file. A dated post can now cite something that does not move.

COR-001 corrected broke 2026-06-01 · found 2026-08-07
We published
Ground beef, wholesale reference $393.06 per pound (cost-index/feed.json, reference.priceUsd, source "bls", basis "wholesale", dated 2026-06-01).
What is true
That figure is the BLS ground-beef INDEX value, not a price. It is not $393.06 per pound and never was. The measured wholesale level for that slug was $5.51/lb (usda-lmr, 2026-06-10) and was published correctly the whole time in cost-index/index.json — the two feeds disagreed by 71x.
Why it broke
Every observation carried its own basis in data/cost-index.json — all five BLS points are labelled basis:"index" — but the series renderer discarded the per-observation basis and stamped the whole file with the ingredient's newest LEVEL basis, which is genuinely "wholesale". A basis is a property of an observation; the code treated it as a property of a file.
Gate that now prevents it
scripts/check-cost-index-basis-leak.mjs
The gate existed and was green. It cross-referenced at the INGREDIENT level, so one true statement about ground beef concealed five false statements about observations. It now resolves every rendered dollar back to its own observation, refuses any figure sourced to a series that publishes indices, and independently flags a 20x step between the reconstructed backfill and the live capture. It also ships a --mutation-proof mode that reintroduces each leak class and asserts the gate goes red, because a gate that has never been shown to fail is not evidence.

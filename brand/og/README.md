# Per-page OG (Open Graph) image cards

These are the 1200×630 social share cards for each indexed page. They
ship as PNG for maximum compatibility (Facebook, LinkedIn, iMessage,
WhatsApp, Slack, and Twitter/X still render raster OGs more reliably
than SVG — Twitter rejects SVG outright). The source SVGs live next
to their PNGs here.

## How cards are built

Every card in this directory is generated by
[`scripts/build-og-cards.mjs`](../../scripts/build-og-cards.mjs)
from an entry in [`cards.json`](./cards.json). The driver:

1. Reads the manifest
2. Picks the template for each entry's `kind` (page | research |
   article | tool)
3. Composes the SVG with the 8px baseline grid, muntin-mark
   leitmotif, category accent, signature ornament, and path-free
   footer
4. Shells out to `rsvg-convert` (on CF Pages) or falls back to
   `@resvg/resvg-js` (local dev) to render a 2400×1260 PNG — 2×
   the declared 1200×630 meta so the card stays crisp on retina
   and when social platforms upscale (LinkedIn feed previews
   render at ~1.5×)

```sh
# Render everything in the manifest
node scripts/build-og-cards.mjs

# Dry-run (lists, no writes)
node scripts/build-og-cards.mjs --dry-run

# Re-render one slug
node scripts/build-og-cards.mjs <slug>
```

The driver is idempotent — skips PNGs newer than their source SVG,
and the SVG is a no-op write when the template output hasn't
changed.

## Authoring a new card

1. Add a row to `cards.json`:
   ```json
   {
     "slug": "my-page",
     "kind": "page",
     "locale": "en",
     "eyebrow": "CATEGORY · CONTEXT",
     "title_1": "First line",
     "title_italic": "middle",
     "title_2": "third line.",
     "dek": "One-sentence description.",
     "focus": { "type": "type" }
   }
   ```
2. Run `node scripts/build-og-cards.mjs my-page`
3. Point the HTML page's `og:image` + `twitter:image` at
   `https://muntin.digital/brand/og/my-page.png`

## Templates

- **page** — cream-forward landing pages (ink bg, Fraunces display,
  muntin-mark focal). Home, About, Services, Learn hub, System, etc.
- **research** — short evidence notes (cream bg, rust accent, one
  focal stat / quote / ring / list per card). Under `/learn/research/`.
- **article** — blog posts (cream bg, teal accent, 3-line display
  with italic flourish, right-column focus module).
- **tool** — audits + calculators (saturated teal bg, gold accent,
  focus = score-ring or checks).

## Focus modules

Each template accepts a `focus` block that selects a right-column
visual:

| `focus.type` | Produces | Typical data |
|---|---|---|
| `type` | Muntin-mark leitmotif only | — |
| `stat` | Big display number + caption + source | `value`, `caption`, `source` |
| `list` | Numbered 3–5 item list | `label`, `items[]` |
| `quote` | Italic Fraunces pull-quote + attribution | `text`, `attribution` |
| `score-ring` | Lighthouse-style gauge with threshold ticks | `value` (0–100), `label` |
| `funnel` | Horizontal stage-by-stage dropoff bars | `data[]`, `lost_label` |
| `checks` | Audit-style pass/fail rows | `items[]` with `label` + `pass` |

## Typography

Rendered via `rsvg-convert` with `FONTCONFIG_FILE` pointed at
`brand/fonts-for-og/fonts.conf`. That config aliases `sans-serif`
→ Inter and `serif` → Fraunces, using the TTFs at
`assets/fonts/pdf/` (self-hosted for PDF export, reused here).

- **Display** — Fraunces (falls back to Georgia if fontconfig fails)
- **Body / labels** — Inter (falls back to Arial)

## Deploy pipeline

CF Pages runs, in order (see `wrangler.jsonc`):

1. `build-og-cards.mjs` — render all cards in the manifest
2. `sync-includes.mjs`, `stamp-hreflang.mjs`, `stamp-es-restaurant-audit.mjs`
3. `check-locale-parity.mjs --check`
4. `check-og-images.mjs` — fails build if any HTML page's
   `og:image` meta points at a PNG that doesn't exist in
   `brand/og/`. Catches stale slugs and forgotten manifest rows.

## Co-located case-study OGs

Case studies that ship with owned photography keep their OG
image next to the case-study content (e.g. `/work/tacombi/og-image.png`)
rather than in `brand/og/`. This isn't a rule — just the pattern
for cards that carry client-specific imagery.

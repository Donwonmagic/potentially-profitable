# Free tools — strategy (captured for the master plan)

**Core finding: the work is MIGRATION + DELETION, not construction.** The five calculators
are genuinely good and honestly built. The problem is uniform: **every tool wins the first
visit and then dead-ends** — and the save→watch→alert→Brief loop the whole retention strategy
rests on is ~90% already coded (market-recost panel, the Lock Book local diff, the Vendor
journal, two cascade.js files) but **unwired, broken, gated behind sign-in, or pointed at
retired tools.** ~Half the connective tissue is still the pre-consolidation 17-tool SEO/
services "museum."

## The stickiness system — build ONCE, wire all five

One shared **SAVE** at the point of value, honest + local-first, no signup:
**"Save this — we'll tell you the month something in it actually moves, and stay quiet when it
doesn't."** (Sign-in = optional cross-device/email upgrade, never the gate.) Each tool writes
its dish/line into the shared `MuntinContext` bus → the market-recost/alert brain (already coded)
→ the event-spike alert → personalizes the monthly Operator's Brief. This is THE wiring that
turns first-visit tools into the between-issue return engine. Materiality-gated, sometimes "no
change — you're fine" (the honesty proof).

# CI, Gates & Delivery Integrity

**NOT_READY**

## Thesis
The plan's gate doctrine is right and its instrumentation is the best thing in either repo — `audit-gate-teeth.mjs` is the first tool at Muntin that measures a gate instead of reading it, and its verdict is damning in exactly the useful way: of 132 gates I ran it against today, 8 were demonstrated to have teeth, 25 shrug at their own corrupted inputs, 3 are already red, and 96 (73%) cannot be judged at all because the instrument only mutates `data/*.json` and most of the corpus scans HTML. But the plan does not reduce net obligation — it adds 7 `check-*` scripts plus 1 `audit-*` (storefront goes to 134 check scripts, 127 wired) and **no queue item retires a single gate**; there is a one-in-one-out budget for documents (`check-working-set.mjs`) and for surfaces (`surface-disposition.json`) but none for gates, which is the corpus that actually costs deploy time and false alarms. Worse, the plan's own artifacts broke two things I could measure right now. **`check-queue.mjs` exits 2 in every mode** — `--brief`, `--budget`, `--checkpoints`, `--render`, even `--self-test` — because Q-004 was closed with `status: "closed"`, a value not in `STATUSES = ['ready','claimed','blocked','done']` (`scripts/check-queue.mjs:96`, enforced at `:238`). The plan's central instrument, the one both session-start hooks invoke and CLAUDE.md tells every session to run first, is dead, and the hook swallows it with `2>/dev/null || true`, so a session gets silence rather than an error. **All ten checkpoint `mustBeTrue` verify commands fail with a shell-quoting `ReferenceError`**, not with "not closed" — `["Q-002", "Q-014"]` inside a double-quoted `node -e` becomes `[Q-002, Q-014]`. The CP-30/60/90 kill criteria that ADR-033 stakes the strategy on will fire red on 2026-09-06 whether or not the work was done, which teaches the founder to ignore the one alarm designed to end the quarter. Separately, `check-removed-slugs.mjs` is WIRED into `check-all` and exits 1 today because `data/link-graph.json` — created by the plan's own bones commit `c1fbd5304` — carries retired slug anchor text, and Q-005's doneWhen (builders present in `build.command` + `check-idem-coverage`, both of which pass) cannot see it. The most important thing still missing is a gate budget: a rule that adding a gate requires retiring one, and a rule that no new instrument ships without its own commands having been executed once.

## Gaps
- **[BLOCKING] check-queue.mjs — the plan's central instrument — is dead in every mode, and the delivery mechanism hides it**
  - `node scripts/check-queue.mjs` (and --brief, --budget, --checkpoints, --render, --self-test) all exit 2 with 'the queue is malformed (1): Q-004: status must be one of ready|claimed|blocked|done'. Cause: data/queue.json Q-004 carries status "closed", written by "orchestrator" on 2026-08-07; the enum is scripts/check-queue.mjs:96, validated at :238, exit 2 documented at :81. .claude/hooks/session-start.sh runs it as `node scripts/check-queue.mjs --brief 2>/dev/null || true` — stderr discarded, failure swallowed. check-queue is deliberately UNWIRED from check-all (scripts/check-gate-coverage.mjs:88), so CI is green while it is dead.
  - Cost: Every session started from now gets a silent no-op where the top queue item should be. The one mechanism the plan added to beat the 26% close rate — pointing sessions at a backlog — delivers nothing, and delivers it invisibly. --budget and --checkpoints cannot run either, so the founder-hour ceiling and the kill criteria are unenforced.
- **[BLOCKING] All ten checkpoint kill-criterion verify commands fail for a shell-quoting bug, not for work-not-done**
  - I executed every `checkpoints[].mustBeTrue[].verify.cmd` in data/queue.json: 10 assertions, 10 failing. The failure is `ReferenceError: Q is not defined` — the commands embed `const need=["Q-002", "Q-014", "Q-001"]` inside a double-quoted `node -e "..."`, so bash strips the inner quotes and node parses bare identifiers. Reproduced at CP-30 assertion 1; identical shape in all four CP-30, three CP-60 and three CP-90 assertions.
  - Cost: On 2026-09-06 CP-30 goes red regardless of whether Q-001/Q-002/Q-014 closed, and the failure is indistinguishable at the exit-code level from a genuine miss. ADR-033 says two of these criteria end the strategy. A falsifier that always fires is not a falsifier; the founder will read the first false red and stop reading. This is the exact defect ADR-023 was written about — a check that has never been SHOWN to run is not evidence — committed by the artifact that cites ADR-023.
- **[BLOCKING] The plan turned a previously-green WIRED deploy gate red, and no queue item can detect it**

It is wired at scripts/check-all.mjs:156. data/link-graph.json was added by commit c1fbd5304 (2026-08-07, 'feat(bones): generate the site inventory instead of writing it down') — a plan artifact. ALLOW_FILES is scripts/check-removed-slugs.mjs:60 and does not cover generated inventories.
  - Cost: check-all runs inside build.command, so this reds the Cloudflare deploy and no agent session reaches production. Q-005 (HIGH, M1, 0.5h, 'Green the deploy') will be closed by a verify command that exits 0 while the deploy is still red — a machine-proved false closure in the first window, which is precisely the failure the queue exists to prevent.
- **[MAJOR] audit-gate-teeth.mjs can only judge 27% of the corpus, and HD-14 will read PAID with 96 gates never measured**
  - My full run: 132 gates measured — HAS-TEETH 8, NO-TEETH 25, ALREADY-RED 3, NO-JSON-INPUT 96. The instrument's `inputsOf()` matches only `/['"`](data\/[A-Za-z0-9._-]+\.json)['"`]/`, so every HTML-scanning gate (check-article-graphics, check-fabrications, check-positioning-drift, check-locale-parity, check-cost-index-basis-leak — the gate the instrument was written about) is NO-JSON-INPUT. NEVER_MUTATE additionally excludes sourced-claims.json, cost-index.json and cost-index-editions.json — the three highest-stakes files. HD-14's check is `a.results.filter(r=>r.verdict==='NO-TEETH').length===0` against static data/gate-teeth-audit.json.
  - Cost: HD-14 closes when 25 named gates are fixed, leaving 96 unmeasured and the corpus certified. 'The gate that could not be shown to fail' (HD-02) is generalized to a fifth of the problem and declared paid. The honesty-debt doctrine — pay in full before amplifying reach — becomes provably partial.
- **[MAJOR] HD-14's proof is a hand-editable static snapshot that had already drifted the same day it was written**
  - data/gate-teeth-audit.json (generatedAt 2026-08-07) records NO-TEETH 24, ALREADY-RED 2, NO-JSON-INPUT 94, 128 gates. - **[MAJOR] No one-in-one-out budget for gates, the one corpus that is growing**
  - The plan added 7 check scripts (check-src-sentinel, check-honesty-debt, check-contract-injection, check-corrections-ledger, check-queue, check-surface-disposition, check-working-set) plus audit-gate-teeth, per `git log --diff-filter=A --since=2026-08-06 -- scripts/`. check-gate-coverage now reports 134 check scripts, 127 wired. Gates get none.
  - Cost: The plan's own diagnosis is that the corpus is mostly shape-assertion — my measurement puts demonstrated teeth at 8 of 132 — and its response is to add 7 more. Every added gate is founder review time on false reds and another entry that must stay green in build.command forever. Without a retirement rule the next plan inherits ~145.

# Evals, Round Two — why the first pass did not take

## Thesis
The 2026-07-30 pass did not fail from bad execution; it failed for three compounding reasons the essay does not address, and one of them is worse than the hypothesis you gave me. First, its flagship commit shipped nothing: `de17b2a`'s 265-line `check-cost-index-snapshot-freshness.mjs` was a reimplementation of `check-cost-index-snapshot-fresh.mjs`, which had lived on main since 2026-07-16 with the exact "parse STALE_AFTER_DAYS out of the resolver" design the commit message claims as its own innovation — and the same session's own merge (`f436b9c`, hours later) deleted it. It is an ancestor of HEAD; the file is not on HEAD. Second, the one commit that produced a real grounding signal, `999a4c122`, was wired `(warn)` at birth: it printed "8 unexpected frozen feeds" on 2026-07-30 and prints "16" today, an unanswered doubling in eight days — the essay's own definition of a report. Third, none of the six commits reads prose, so none could see the 72 falsehoods, the five out-of-chain builders blocking the deploy, or the Stripe seat multiplication at `billing.ts:174-175`. Your hypothesis is confirmed but understated: the pass added grounding checks to the machine-generated layer, which was already the best-instrumented layer, and left the hand-written layer — the only one a human authors, and the only one where the honesty differentiator actually lives — at zero coverage. The deeper lesson is not about evals at all: the workforce cannot see what the workforce already built, so an eval program that is not itself indexed against `origin/main` will be rebuilt rather than run. Build three deterministic evals (published-number faithfulness, promise-mechanism, falsifier reachability), fund each by retiring a check-all entry, and let a scheduled session — not the founder — work the queue.

## Design
### E0 — The trace corpus, generated not written (`evals/traces/build-corpus.mjs` → `evals/traces/corpus.json`) [One session. Read-only over `findings.json` + git.]
A script that emits one trace record per real failure by joining `docs/handoff/company-audit-2026-08-07/findings.json` (235 findings, each with `evidence`/`verdict`) against `git log --name-only` for the file each finding cites. Record shape: `{id, surface, claimAsPublished, groundTruthCommand, groundTruthValue, verdict, attribution, introducedBy, detectedBy, closedBy|null, daysOpen}`. `attribution` is a required enum: `agent | dependency | founder-absence | environment | unclear`. Paired records are mandatory — every FAIL trace is stored beside the nearest PASS on the same surface (e.g. `check-cost-index-snapshot-fresh` next to the deleted `-freshness` duplicate; the enforced `<!-- count: -->` sentinel next to the unenforced `<!-- src: -->`).

- Naive: Author ~25 hand-written eval cases as a fixed test set, per the travel-agent example.
- Evolved: Muntin already has 235 evidenced failures and ~370 scripts; a hand-written set would sample the wrong distribution and would rot the moment the tree moved — exactly what happened to the 16 planning docs and the 2,481-line board. Generating the corpus makes it regenerable, and the `attribution` field is the piece the source material omits: without it the pass could not tell you that `de17b2a` was `agent` (branch blindness) while the frozen NOAA feeds are `dependency` and the warrant canary is `founder-absence` — three failures needing three different mechanisms.

### E1 — FAITHFULNESS eval: a published number that is no longer true (`evals/eval-published-number.mjs`) [One session for the gate + freeze writer. A second session to write the freeze for the five live editions retroactively from `cost-index/week-*.json` plus git blame at each publish commit.]
For each page, extract numeric literals from prose spans that either carry a `<!-- src: -->` annotation or sit inside/adjacent to a `<details class="cite">` whose `class="cite-source"` names an internal `data/*.json`. Resolve each against two references: the page's publish-time freeze (`blog/<slug>/evidence.json`) and the live file. Three verdicts: **STABLE** (matches live) → pass; **DATED-HONEST** (differs from live, the sentence carries an explicit as-of date, and the freeze exists and matches) → pass, logged; **UNGROUNDED** (unqualified present tense, or no freeze, or freeze disagrees with what shipped) → FAIL. Ships with the freeze writer wired into `build-cost-index-dispatch.mjs`, so every future edition is born with its evidence.

- Naive: Fail on any divergence between published prose and live data — the `check-src-sentinel.mjs` design named rung 0 in the frontier doc.
- Evolved: Two reasons it would die here. (a) Scope: only one page on the site carries `<!-- src: -->`, so as designed it guards 1 of 1,368 pages. (b) Signal: the July dispatch already date-qualifies 85 sentences with "as of 2026-07-06", and a publication *of record* is supposed to disagree with live data — binary faithfulness would raise ~72 findings of which the founder would correctly dismiss most, on a feedback loop already running a 37.5% phantom-red rate. Three verdicts converts an unownable 72-item list into roughly fifteen real ones: the unqualified present-tense claims ("holds 2,080 entries", live 10,294) and the inverted outlook.

### E2 — PROMISE-MECHANISM eval: a promise with no mechanism behind it (`evals/eval-promise-mechanism.mjs` + `data/promises.json`) [One session for the registry + gate with the five seeds. Item (1) is the highest-value 15 minutes in the company and this makes it permanent.]
A registry where every reader-facing promise of *future action* carries the executable assertion that discharges it: `{id, promiseText, pagesMatching (a glob or grep), mechanism: {file, assertion}, owner, registeredAt}`. Seeded from measured breakage — (1) "first Tuesday" monthly email on 83 pages ⟷ `src/worker.js:8793` `sub.source !== 'cost-index'`, asserted by comparing the subscribe forms' emitted `source` values against the broadcast allowlist; (2) "re-checked in CI" at `:852` ⟷ the existence of E1 covering that page; (3) `ledger.muntin.digital` on 405 pages ⟷ a route pattern in either repo's wrangler config; (4) the warrant canary's monthly cadence ⟷ its own date header; (5) `llms.txt:25` "publishes weekly" ⟷ the 2026-07-09 monthly decision. Plus a bounded detector matching only the four verbatim promise templates the site actually uses, so a new page inheriting the footer promise auto-registers.

- Naive: A prose scanner that regex-detects promissory language site-wide and flags unbacked promises.
- Evolved: This repo has learned three times — and wrote it into CLAUDE.md as a rule — that a scan is only as good as its root list, and that widening a scan without fixing the cause produces noise. 1,368 pages of deliberately careful prose would return hundreds of hits. Registration inverts it: the registry is additive, small, and every entry is a *runnable* assertion rather than a note, so it cannot degrade into the fourteenth registry. The bounded detector exists only to stop the registry silently under-covering as pages multiply.

### E3 — FALSIFIER-REACHABILITY eval: a claim whose falsifier is unreachable (`evals/eval-falsifier.mjs`) [One session. The manifest half is free; the network half is ~30 lines guarded by an env flag.]
For every reader-visible invitation to verify — a cite drawer naming a file, a `used_in` edge in the public `/claims.json`, the CC0 per-week dataset links, the DataCite record, `no-llm-ci.sh`'s public claim — assert the artifact a stranger would actually fetch is (a) present in the **deploy tar manifest**, (b) reachable at the URL the page prints, (c) contains the cited key. Runs in two modes: manifest-only in `check-all`, and one HEAD request per distinct host in `freshness-heartbeat.yml` (already scheduled Saturdays, already opens a rolling issue).

- Naive: `existsSync()` on the cited path, which is what seventeen storefront gates already do for local hrefs.
- Evolved: Disk presence is not reachability here, and the gap is asymmetric in the dangerous direction: `docs/` is excluded from the deploy tar while `data/` (~32MB) is served and crawlable, so a gate that checks disk can pass on a file no reader can fetch and vice versa. And `ledger.muntin.digital` — 547 occurrences across 405 pages, plus the product's own canonical URL — is unreachable by a mechanism no `existsSync` can model. This becomes the **first network I/O in 129 storefront gates**, deliberately confined to one gate, one scheduled workflow, and one HEAD per host so it can never become a flaky blocker on an unrelated PR.

### E4 — The scoreboard, and the one-in-one-out that funds it (`evals/run.mjs`, `evals/scoreboard.json`) [One session for the runner + the retirement rule. The 56-entry move is a second session and is the highest-ratio cleanup in the repo.]
One command, one exit code, three numbers: faithfulness %, promise-discharge %, falsifier-reachability %, each with the count of traces behind it and a delta against last week. It is a **separate binary from `check-all`**, with its own report written to `docs/evals/` by the Saturday heartbeat. Paired with a hard rule enforced by `check-gate-coverage.mjs`: adding an eval requires naming a `check-all` entry retired in the same commit. First payment: move the **56 tautological `(idem)` entries** — builders the deploy runs immediately before `check-all` asks them whether their own output is their own output — into a pre-builder `check-drift.mjs` job where they carry information.

- Naive: Register the three evals in `check-all.mjs` alongside the other 320.
- Evolved: `check-all` went ~90 → 320 in 33 days, has never retired anything, takes 186 seconds, and 3 of the 8 reds a founder sees locally are phantoms the deploy heals. Adding to that corpus lowers the signal-to-noise of green, which is precisely how the 07-30 pass made things worse rather than better. A separate binary means an eval red is unambiguous, and one-in-one-out is the only mechanism in this design that makes measurement *cheaper over time* instead of monotonically more expensive against 13–26 founder-hours.

### E5 — The queue worker: a scheduled session, not a founder reading a list (`.github/workflows/evals-weekly.yml` + `evals/queue.md`) [One session to wire, given the four existing cron workflows as the template. This is the component that makes the other five matter.]
A weekly workflow that (a) runs `evals/run.mjs`, (b) appends every new FAIL to `evals/queue.md` with its trace id and ground-truth command, (c) fires a Claude session whose brief is 'work the top three items in evals/queue.md, one commit each, close by writing the trace id in the commit body'. Write permissions are split by role: the **runner** may write only under `evals/`; the **fixer** may write code but never under `evals/` (so it cannot make a failing eval pass by editing the eval); **protected paths** always route to the founder — `.github/workflows/`, `wrangler.jsonc`, `src/worker.js`, `apps/api/src/routes/billing.ts`, `migrations/`, `data/sourced-claims.json`. `evals/accepted.json` tracks cost per accepted change; the workflow disables itself below 50% acceptance over the trailing 10.

- Naive: Write the findings into the strategic board and the backlog, ranked, with effort estimates.
- Evolved: That is the measured null: 26% close rate, and **zero closures in company history came from anyone working an audit's list**. Four cron workflows already diff-and-open-an-Issue and no session has ever been pointed at that queue. The founder's hours are 13–26/mo against ~53 of obligation, so any design whose critical path runs through him reading a document is already known to fail. Splitting by write permission is the one piece of the software-factory pattern that transfers intact, and it is what makes an eval a gate the fixer cannot bribe.

### E6 — `evals/index.json`: the branch-aware gate index that would have prevented `de17b2a` [One session. The generator is a directory walk plus a regex for `readFileSync`/path literals; the pre-commit check is ~40 lines.]
A generated inventory of every `check-*.mjs` and every eval in both repos: `{name, subjectFiles (the paths it reads), assertionClass: SHAPE|GROUNDING, wiredIn, lastFiredAt}`. Regenerated by script, loaded into sessions via `@evals/index.json` from CLAUDE.md rather than prose. The enforcing half is a pre-commit assertion: a new `check-*`/eval script whose **subject set** overlaps an existing gate's subject set **on `origin/main`** — not on the working branch — fails with the name of the gate it duplicates.

- Naive: Add a 'gates we already have' section to CLAUDE.md, or write the inventory into the strategic board.
- Evolved: `de17b2a` is the disproof of prose memory. That session followed every CLAUDE.md convention perfectly — a self-test, a dated reason, wired in the same commit, verified against the real regression — and still produced 265 duplicate lines, because the gate it duplicated existed only on a branch it had not merged. No amount of prose in a file that loads at session start can carry what only `origin/main` knows. And CLAUDE.md is already 113 + 213 lines against a 200-line ceiling, so this must be an import, not a section. Indexing by *subject file* rather than by name is the load-bearing choice: `-fresh` vs `-freshness` would defeat any name check.

### E7 — Judge hygiene as blind re-derivation (`evals/judge.md`, `evals/judgments.jsonl`) [One session to write the protocol and retro-score the 10 highest-severity audit findings under it, producing the first calibrated severity list.]
A pinned protocol: the judge is a different model family from the maker; it receives ONLY `{claim, file path, line}` — never the maker's reasoning, severity, or confidence; it must run its own command and produce the value itself before it may agree; verdicts are `REPRODUCED | REFUTED | CANNOT-REACH`, and CONFIRMED requires **two independently derived values agreeing**, not one agent finding another's argument persuasive. Judge model id, prompt hash, and command line are logged per verdict.

- Naive: An adversarial verifier handed the maker's finding report and instructed to refute it — this audit's phase-1 protocol.
- Evolved: Measured on this audit: the adversaries refuted **1 of 235** (0.4%) — 100 CONFIRMED, 82 ADVERSARY, 50 PARTIAL, 2 NOVERDICT, 1 REFUTED — while an independent critic re-checking 10 findings later found 2 contradicted by their own cited evidence, a 20% error rate that projects to roughly 47 bad findings. A 0.4% refutation rate against a ~20% true error rate is not evidence of good auditing; it is evidence of a compromised judge grading the coherence of an argument it was shown. My own blind re-derivation of the flagship page's numbers in this session both confirmed the drift and corrected the audit's headline: the '72 falsehoods' figure conflates date-qualified of-record numbers with genuinely unqualified present-tense claims, which is why E1 has three verdicts and not two.

## Advance
- **A three-verdict faithfulness eval — STABLE / DATED-HONEST / UNGROUNDED — where a published number that disagrees with live data PASSES if the sentence is date-qualified and a publish-time freeze exists and matches.**
  - Gap: Every eval framework in the packet treats faithfulness as binary against a current ground truth. A publication of record cannot work that way: a dated edition is *supposed* to diverge from live data, and the July dispatch already date-qualifies 85 sentences. Binary faithfulness would have raised ~72 findings the founder would have been right to dismiss, on a loop already 37.5% phantom — reproducing the exact failure this panel exists to fix. The three-verdict form is what turns an unownable list into ~15 real fixes, and it names the *mechanism* the fix needs (a per-post `evidence.json` freeze) rather than a renumbering chore that recurs every refresh.
- **Blind re-derivation as the judge contract: the judge produces the value itself, CONFIRMED means two independent derivations agree, and CANNOT-REACH is a first-class verdict.**
  - Gap: The source material says the judge must not see the maker's reasoning and stops there — it never says what the judge should *do* instead. That gap is measurable here: this audit's adversaries, handed the maker's reasoning, refuted 1 of 235 while the true error rate on a 10-finding re-check was ~20%. Blinding alone would not have fixed it, because a judge with only the claim can still nod along. Requiring re-derivation makes the judge's cost proportional to the claim's stakes and makes unreachability (no network, no dashboard, no bank balance — the audit's own §5 blind spot) an explicit output instead of a silent CONFIRMED.
- **One-in-one-out as the funding model for measurement: an eval may only be added against a named `check-all` retirement, enforced by the existing meta-gate.**
  - Gap: Every source tells a company to add measurement; none tells a one-person, pre-revenue company what to remove to pay for it. Muntin went ~90 → 320 gates in 33 days, retired nothing, and made its founder's only feedback loop 37.5% false-alarm. The retirement rule is derived from this company's measured failure, not from any essay, and it has an obvious first payment: 56 of check-all's 320 entries are tautologies the deploy creates by running the builder immediately before checking it.
- **Branch-aware, subject-indexed duplicate detection as a memory primitive — index a gate by the files it reads, checked against `origin/main` rather than the working branch.**
  - Gap: The memory-engineering material models one store and worries about contradiction; it has no model of a parallel agent workforce on divergent branches, where the failure mode is not contradiction but *reinvention*. `de17b2a` is the proof: 265 lines, a real-regression verification, 14 self-test assertions, a flawless commit message — all a second copy of a 14-day-old gate, all deleted by its own author's merge, and all of it invisible to CLAUDE.md, to the board, and to both meta-gates. Name-matching would not have caught it (`-fresh` vs `-freshness`); subject-matching would.

## Rejected
- **LLM-as-judge inside the content evals.** The company's sharpest public differentiator is `no-llm-ci.sh` — 'no language model reads your numbers', falsifiable by a stranger in thirty seconds. Putting a judge model into the grading loop for cost-index numbers either violates that gate or forces a documented exception, and the exception costs more credibility than the eval returns. All three headline evals are deterministic scripts. Reserve model judging for reviewing agent *sessions*, which lives outside the gated tree.
- **The full software-factory graph** — worktree-per-worker, parallel fan-out, joins, recovery, earned autonomy tiers. That is a throughput solution, and throughput is not the measured bottleneck: 266 of 344 commits in 60 days landed on 8 days, and 80–84% of commits are already agent-authored. More parallel artifact production against 13–26 founder-hours makes the ratchet worse. Take exactly two pieces — split by write permission, and protected paths — and leave the rest.
- **'Measure the path, not just the answer' implemented as new trace instrumentation.** Building per-session capture of tool calls and reasoning paths is real infrastructure with a real maintenance bill. Here the path is already recorded, free, and unusually rich: `git log` plus commit bodies that routinely explain what was tried, what was rejected, and why (`e14ca9b`'s 'NOT DONE, deliberately' is a better trace than most instrumentation produces). Mine that. A second observability layer would become the seventeenth registry.
- **CLAUDE.md rule-adherence review as a standing cadence** (run a session, have a second session grade the transcript rule-by-rule). Worth doing once, as calibration. Not worth a recurring slot, because the measured failure is not disobedience — `de17b2a` obeyed every convention in CLAUDE.md and still shipped a duplicate that got deleted. The problem is that CLAUDE.md structurally cannot contain what only `origin/main` knows. A generated `@evals/index.json` costs one session and fixes the actual cause; a recurring transcript audit costs founder-hours forever and would have graded that session a pass.
- **The '25 traces' target, and every statistic in the source packet, as a number.** Take the mechanism — good and bad side by side, attribution recorded — and reject the count as a goal; Muntin has 235 evidenced findings and the corpus size should be an output of the generator, not an input. Likewise, nothing in this design cites '19 of 20 PRs merge unreviewed', '97% error reduction', '83.9% vs 32.3%', or '47x' as fact. They are secondhand and unregistered, and this client's own fact gate would reject them on a public page; it should reject them here too.

# The Contract — CLAUDE.md, progressive disclosure, and verified adherence

## Thesis
The premise underneath every CLAUDE.md recommendation — "the file loads into every session, so every line must earn universal applicability" — is false at Muntin, and that is measurable, not arguable: of the 56 unique agent sessions in this very engagement (the largest in company history, 3,363 Bash calls), exactly **1** had a CLAUDE.md injected, despite 37 running with cwd = the storefront repo root. The workforce is workflow subagents, and workflow subagents do not load the contract. Every rule that was actually followed was followed because the orchestrator hand-copied it into the task prompt — board-read in 41/56 prompts, root-list discipline in 14/56, the fact gate in 16/56 — which is progressive disclosure implemented by copy-paste, lossy and unmeasured. So pruning the file is the second job; **routing it is the first**, and the split must be built so that the compiler that assembles a subagent prompt can select scope-relevant sections mechanically. Second: the contract's own facts have rotted worse than anything it governs — it says `scripts/` holds "~70" scripts when there are 380 (5.4x), cites "1428 pages" against 1,314, and contradicts itself inside a single bullet ("96 `(idem)` builders" and "83 builders", line 51). A file that publishes wrong numbers cannot be the enforcement instrument for a fact gate; its factual claims must be **compiled from `data/system-graph.json` and `data/surface-inventory.json`**, which the Bones phase already built today, not typed by hand. Third, the emphasis channel is already dead without a single `IMPORTANT` or `YOU MUST` ever being used: the storefront file carries **64 bold spans across 113 lines**, the product **61 across 213** — adding the source material's markers would open a second diluted channel, so cap bold instead. Finally, adherence must stop being a ritual and become a number: rules get ids and machine detectors, adherence is computed from transcripts on disk, and a rule that no session fires in 90 days is proposed for deletion — because the one thing this company has never done to any artifact is retire it.

## Design
### 1. Fix the load path FIRST — `scripts/lib/contract.mjs` + a scope-selecting prompt preamble [1 agent session]
A module exporting `contractFor(paths[]) -> string`, which reads `docs/contracts/rules.json` (component 3) and returns only the rule blocks whose `scope` globs intersect the paths a task will touch, plus the always-on core. Every workflow script that spawns a subagent (the `workflows/scripts/*.js` generators) prepends `contractFor(...)` to the child prompt. Ships with `scripts/check-contract-injection.mjs`: parses every file under `.claude/workflows/` and `workflows/scripts/` for a spawn call, and fails if any spawn builds a prompt without calling `contractFor`.

- Naive: Prune CLAUDE.md to under 200 lines of universally-applicable rules and trust that it loads.
- Evolved: It does not load. 55 of 56 sessions in this engagement — including all 5 that wrote code — ran with zero CLAUDE.md, so a perfectly pruned file would have changed nothing about this engagement. The orchestrator already does this by hand (board-read language in 41/56 prompts, root-list in 14/56), which means the mechanism is proven and only the hand-copying is the defect. Mechanizing it also makes the *scope* metadata load-bearing, which is what makes components 2 and 6 possible.

### 2. Progressive-disclosure split — named files, both repos [1 session per repo (2 total)]
Storefront root `CLAUDE.md` → ~45 lines: identity, the retirements/on-funnel scope rule, where-things-live, the fact gate in one paragraph, slugs-are-final, the compiled FACTS block (component 4), and pointers. Move out to: `@docs/contracts/prose.md` (voice canons index, bylines, banned words, cite-drawer rules), `@docs/contracts/gates.md` (root-list discipline, gate-coverage, idem-coverage, positioning-drift, the never-wire-a-failing-gate rule). Nested files: `library/CLAUDE.md` + `blog/CLAUDE.md` (viz-* families, data-audio-alt ≥80, figcaption, autolink sentinels, byline), `cost-index/CLAUDE.md` + `data/CLAUDE.md` (dispatch cadence, spine commensurability, driver layer, editor's note, honesty contract), `scripts/CLAUDE.md` (root-list discipline, registry duties, determinism/no-wall-clock), `assets/CLAUDE.md` (image dims/formats/lazy). Product root → ~60 lines: identity, monorepo layout, microcopy EN↔ES, environment honesty, branch-and-deploy discipline, gate-wiring rule, ADR format. Nested: `apps/api/CLAUDE.md` (ingest pipeline, statuses, inventory routes, valuation ladder, stores, migrations/db-verify), `apps/web/CLAUDE.md` (copy.ts, a11y gates, locations client/server bleed, OpenNext), `services/extract/CLAUDE.md` (determinism / no-LLM gate, harvest rules), `infra/postgres/CLAUDE.md` (RLS-first, db-verify).

- Naive: Split by section heading, one nested file per app shell listed in CLAUDE.md — six shells, six files.
- Evolved: Split by measured traffic, not by org chart. Over 583 product commits/90d: apps/api 186 (32%), services/extract 158 (27%), apps/web 135 (23%) — while apps/ios, apps/mobile, apps/desktop and apps/email-worker do not appear in the top 16 trees at all. Four of the six shells get no file; they get one line each in root saying they are low-traffic and to read the package README. Same on the storefront: the audio pipeline is 6 root lines serving 3.2% of commits, so it becomes `docs/contracts/audio.md` behind an import rather than a nested file, because nothing routinely edits an audio JSON without being told to.

### 3. `docs/contracts/rules.json` — the rule as a first-class record [1 session]
One JSON file per repo. Each rule: `{id, text, scope: [globs], addedOn, why (the incident), enforcedBy: 'gate:<script>' | 'prompt' | 'none', emphasis: 0|1, detector: null | {kind, pattern}, lastFiredOn, adherence: {n, ok, at}}`. CLAUDE.md and the nested files are **generated** from it by `scripts/build-contract.mjs` between `<!-- contract:start -->` sentinels, `--check` wired into check-all. Rendering caps `emphasis:1` at 8 rules per file; the builder fails if more are marked.

- Naive: Hand-edit CLAUDE.md and reserve IMPORTANT / YOU MUST for costly misses.
- Evolved: Both files have used IMPORTANT zero times and are already emphasis-dead via 64 and 61 bold spans — the channel was exhausted by an unmanaged marker, so adding a managed one on top of an unmanaged one just adds a channel. A hard cap enforced by a builder is the only version that survives this company's additive reflex (90 → 320 gates in 33 days, nothing ever retired). Making `scope` a machine-readable field is also what lets component 1 select and component 6 measure; prose cannot do either.

### 4. `scripts/build-contract-facts.mjs` — compile the numbers, stop typing them [1 session]
Regenerates a sentinel-delimited FACTS block inside each CLAUDE.md from artifacts that already exist: `data/system-graph.json`, `data/surface-inventory.json`, `data/link-graph.json`, plus `git rev-parse --abbrev-ref HEAD`. Emits script counts by family, page counts by tree, gate counts, builder counts by coverage class, and the current branch. `--check` wired into check-all so a stale number reds the build.

- Naive: Correct '~70' to '380' and move on.
- Evolved: Correcting it by hand recreates the same decay site — it was correct once too. This is comprehension rot at the contract layer, and the Bones phase shipped the cure today (build-system-graph / build-surface-inventory / build-link-graph, written 2026-08-07) without anyone pointing it at the file that most needs it. It also removes a genuine integrity problem: a company whose whole differentiator is not publishing numbers it cannot stand behind currently mis-states its own repo by 5.4x in the file that governs its fact gate.

### 5. `scripts/check-contract-coherence.mjs` — make contradictions impossible, not pruned [1 session]
Declares a small set of mutable single-source facts (current branch, dispatch cadence, gate/script/page counts, bio framing, dated section headers). The gate walks CLAUDE.md, all nested CLAUDE.md files, `docs/contracts/*`, `docs/handoff/strategic-council-board.md` and `docs/editorial/decisions/ADR-*.md`, and fails on any *restatement* that disagrees with the source, and on any '(as of YYYY-MM-DD)' header older than the newest dated entry beneath it. Fixes today's four-way branch disagreement and the product file's 2026-07-10 header over 2026-07-30 entries.

- Naive: 'Prune contradictions' — read the files and resolve conflicts by hand.
- Evolved: The source material names the problem and supplies no detector, so it degrades into a one-time cleanup — which is precisely the shape of the 26% close rate: the fix lives only inside the session that found it. Four artifacts currently disagree about the current branch; a hand-prune fixes four strings and leaves the mechanism that produced them. Restricting the gate to a declared list of ~8 mutable facts keeps it cheap and out of the 56-tautology trap: it never asserts a shape, it asserts that two committed statements about the same mutable fact agree.

### 6. `scripts/eval-adherence.mjs` — adherence as a measured number, from real traces [1-2 sessions]
Reads `~/.claude/projects/**/agent-*.jsonl` (and the `subagents/workflows/*/` tree), reconstructs per-agent cwd + tool calls + written paths, then for each rule in rules.json whose `scope` intersects a session's writes, runs its `detector` against the diff/content that session produced. Emits `docs/contracts/adherence.json` — per rule: sessions in scope, sessions compliant, sessions that never saw the rule. Writes findings to the existing cron-Issue queue rather than a report file.

- Naive: Run a real session, then have a second session review the transcript rule-by-rule for what was followed, ignored, or followed inconsistently.
- Evolved: That is a founder-hour ritual in a company paying ~10% of the maintenance hours it already owes, and it produces a report — which by this company's own measured history has a 26% chance of ever being worked. The evolved version keeps the mechanism (a reviewer that reads the trace) and removes the recurring human cost by giving each rule a detector once. It is also the only version that can produce the finding this panel produced: 'the rule was obeyed 5/5 times and reached the agent via the prompt, not the file' requires counting across sessions, which no single-transcript review can do.

### 7. The decay clause — a rule that never fires gets proposed for deletion [1 session]
`scripts/check-contract-decay.mjs` reads adherence.json + rules.json. Any rule with `enforcedBy:'gate'` whose gate has not failed in 180 days, or any rule with zero in-scope sessions in 90 days, is printed as a DELETE CANDIDATE with its `addedOn` and `why`. It never deletes; it produces a dated list the founder approves or rejects, and a rejected rule gets `reviewedOn` so it does not re-surface for 90 days.

- Naive: Add a forgetting policy to the memory store — dedup, consolidate, decay.
- Evolved: Applied to the 2,481-line board it is a large project with an unclear owner. Applied to the contract it is small, and the contract is where a stale rule costs the most, because it is the only artifact that (should) load into every session. Concrete candidate today: CLAUDE.md:51 calls `inject-knit-rail.mjs` 'the highest-churn manual one — run it after any article add, freeze, or retire'; 59 library/blog articles were added in 30 days, the script has not been committed to since 2026-07-05, it is absent from the 84-step `wrangler.jsonc` build.command, and `node scripts/inject-knit-rail.mjs --check` today reports 'would update 0 article(s); 105 skipped.' The rule bought nothing and spent attention in every session that read it.

### 8. Close the writer-side hole this engagement just opened [1 session]
Register the 6 builders written on 2026-08-07 (`build-content-intent`, `build-system-graph`, `build-surface-inventory`, `build-link-graph`, `build-prior-decisions`, `rebuild-all`) in `check-idem-coverage.mjs`'s MANUAL registry with owner + drift condition — or, for `build-prior-decisions`, an explicit NEVER-WIRE entry matching its own header. Then widen `check-idem-coverage` to enumerate `scripts/build-*.mjs --check` modes **on disk** rather than only those already inside check-all, and add the resulting rule to rules.json with scope `scripts/**`.

- Naive: Note in CLAUDE.md that new builders must be registered.
- Evolved: That note already exists (CLAUDE.md:51) and the engagement violated it within hours: six new builders, zero in check-all, zero in the MANUAL registry, and `check-idem-coverage` still reports '83 builders — 0 unhealed' because it enumerates only builders already inside check-all. This is the audit's §1.2 blind spot reproduced live by the audit itself, which is the strongest possible argument that a prose rule without a scope-matched detector is decoration. Doing this in the same pass proves the rules.json → detector loop on a case where the prose rule demonstrably failed.

## Advance
- **Replace the universal-applicability test with a LOAD-PROBABILITY × RELEVANCE test, and fix load before pruning. A rule's value is `P(the session sees it) × P(the session is in scope)`. Measured here, P(sees it) = 1/56 = 1.8% for CLAUDE.md and up to 73% for a hand-copied prompt line, so the file's *routing* is a ~40x larger lever than its *content*.**
  - Gap: The source material treats 'the file loads into every session' as an axiom and derives the entire pruning discipline from it. It gives no guidance for a workforce of workflow subagents, which is exactly what this company runs, and where the axiom is false. Without measuring the load path, a team can do the pruning work perfectly and change nothing — which is a precise model of why the 2026-07-30 eval-engineering pass shipped 14 gate commits and moved the close rate zero points.
- **Contract facts must be COMPILED from repo artifacts, not written. Hand-written counts in a governance file rot at the same rate as any other prose, and rot invisibly because nothing scans a Markdown file for arithmetic.**
  - Gap: The source material names comprehension rot as a bill you pay ('the repo grows, your map of it doesn't') and separately proposes the Karpathy compile-the-wiki pattern — but never connects them, so the wiki gets compiled while the CLAUDE.md that points at it stays hand-typed. Muntin proves the connection is load-bearing: the contract is off by 5.4x on its own script count and 8.7% on its page count, inside the company whose sole differentiator is not publishing unbackable numbers.
- **Contradictions need a DETECTOR, not a prune — implemented as declared single-source mutable facts plus a coherence gate that fails on divergent restatement.**
  - Gap: 'Prune contradictions — two conflicting rules get resolved arbitrarily' is a diagnosis with no mechanism, so it can only ever be a manual sweep. In a company with a 26% close rate and zero closures ever produced by working a list, any recommendation that terminates in a manual sweep is a recommendation to do nothing. The four-way branch disagreement across CLAUDE.md, the board header, the board CURRENT STATE, and actual HEAD is what a prune-only discipline leaves behind.
- **Adherence should be a field on the rule, computed from transcripts, and the trigger for retirement — closing the loop the source material leaves open at 'verify adherence.'**
  - Gap: Eval engineering says 'any failure you do not turn into a permanent test, you will meet again' but stops at the artifact; memory engineering says 'add a forgetting policy before the store grows' but aims it at the memory store, never at the rulebook. Nobody joins them, so rules accumulate exactly like gates did (90 → 320 in 33 days) with no counter-pressure. Making a rule's own measured firing rate the retirement trigger is the only forgetting policy a one-person company can afford, because it costs zero founder-hours until it produces a dated candidate list.

## Rejected
- **'Under 200 lines' as the target.** Wrong unit for this company. The storefront file is 113 lines and still ~82% irrelevant to the sessions that actually run (0 of 56 touched a figure, an audio JSON, a dispatch, or any prose); the product file is 213 lines and still *under*-serves apps/api, which 32% of its commits touch. Budget scope-weighted tokens per session type, not lines per file.
- **Introducing IMPORTANT / YOU MUST markers.** Both files have used them zero times and are already emphasis-saturated at 64 and 61 `**bold**` spans. Adding a second emphasis channel on top of an exhausted unmanaged one dilutes both. Cap bold at 8 spans per file via the builder instead; that is the same discipline with the marker this company actually uses.
- **The five-store memory stack (standards / project / fragile / handover / vocabulary).** Five stores for a one-person company is the additive reflex that produced 320 gates, ~70 runbooks, 16 planning docs and 2,481 board lines with nothing ever retired. One `rules.json` per repo plus the existing board is the whole affordable store. If a sixth artifact is ever needed, the decay gate should have retired something first.
- **'Run a real session, then have a second session review the transcript rule-by-rule' as the standing practice.** Keep it exactly once, as the bootstrap that writes the detectors; reject it as a recurring ritual. At ~53 obligation-hours/month against 13–26 available, a recurring manual transcript review is an obligation this company will not pay — the measured payment rate on existing obligations is ~10%.
- **A gate that asserts CLAUDE.md 'contains' a rule.** That is a shape assertion and would join the 56 tautologies in check-all: it would go green while 55 of 56 sessions never saw the file. Every contract gate proposed here asserts either a cross-artifact agreement (coherence), a recomputed value (facts), or a measured session outcome (adherence).
- **Nested CLAUDE.md for every app shell listed in the monorepo layout.** apps/ios, apps/mobile, apps/desktop and apps/email-worker do not appear in the top 16 trees across 583 commits in 90 days. Four more files nobody loads is four more decay sites; give them one line in root and a package README.

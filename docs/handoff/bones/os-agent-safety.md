# The Four Bills — comprehension rot, cognitive surrender, verification debt, and the review architecture for a one-person agent workforce

## Thesis
You are already outside the loop, and no amount of reading will put you back in: agents added 41,293 hand-authored lines to the storefront in 33 days and 238,706 to the product in 60, against exactly one human code commit in each window and 13-26 available hours a month — a 20-40x gap that widens every week. So the answer cannot be "read more"; it has to be selection, and the good news is measurable: normalized patch-shape hashing collapses your merge diffs 12-33x (PR #520: 1,262 files → 53 shapes; #528: 768 → 40; #526: 1,359 → 105), and it discriminates — PR #525 refused to compress (1,399 → 432, 387 unique edits), which is precisely the PR that most needed your eyes. Build the review architecture on three legs: a shape-compressed review ledger, a short protected-path list where you read the literal bytes and sign for them in a commit trailer, and a weekly random sample whose escaped-error rate is *measured* rather than assumed. Do not add gates — 320 checks at 67.5% shape and a 37.5% phantom-red rate is exactly why PR #536 merged with three reds you accepted, and that acceptance is the first observable symptom of cognitive surrender, not a footnote. Cap merge volume at your review budget: agent output beyond what you can review is not throughput, it is unreviewed liability, and 72 live falsehoods on the flagship post is what that liability looks like when a stranger calls it. Two risks you are not currently worried about will hurt you first — there is literally zero spend governance in either repo, and three workflows run an error-swallowed `git checkout -- .` unattended; and reader-authored prose already flows into a committed data file that agents read, on two public repos, while your stated next move is to point scheduled sessions at an Issue queue anyone on the internet can write to. Split the workforce by write permission, not by task: anything that reads untrusted text holds no keys and returns only a fixed schema. Finally, make comprehension a scored quantity that gates expansion — if you cannot answer 6 of 10 cold questions about a subsystem, that subsystem takes no new agent work until you can, which is also the only retirement forcing-function this company has ever had.

## Design
### 1. The Review Surface Ledger — `scripts/review-surface.mjs` [One agent session (~4h) to write and validate against the 5 measured PRs; ~15 founder-minutes to sanity-check its output on a PR he remembers. Recurring cost: ~40s of compute per PR.]
A script that takes any two revisions (or a PR merge sha) and emits the human review surface, not the diff. For each changed file it hashes the added/removed lines with all digits normalized to `#`, groups files by that hash, and prints: total files, distinct patch shapes, singleton count, and the shapes ranked singletons-first. Each shape is labeled MECHANICAL when its hash matches a signature registered by a known injector (nav/footer/count-sentinel/CSS-cache-bust/autolink) or NOVEL otherwise. Output is a one-page markdown agenda: 'read these N hunks; the other M files are K repetitions of shapes you have already accepted.' A companion `--register` mode teaches it a new injector signature. Reference measurements already taken: #520 1,262 files → 53 shapes (49 singletons); #528 768 → 40 (31); #535 1,317 → 101 (90); #526 1,359 → 105 (top 6 shapes cover 961 files); #525 1,399 → 432 (387 singletons).

- Naive: 'Require human review on every PR' / enable branch protection with a required reviewer, per the software-factory pattern's protected-path idea.
- Evolved: CODEOWNERS already exists in the product repo (`* @donwonmagic`) and has produced zero review comments, because the reviewer and the sole approver are the same person facing 1,673-file diffs. Requiring review of an unreadable artifact produces rubber-stamping, which is what the record shows. The evolved version changes the *unit* of review from the file to the patch shape, which is where this codebase's redundancy actually lives — injector-driven repetition across 1,368 near-identical pages. It also yields a free triage signal the source material has no equivalent for: shape count, not file count or line count, predicts review load, and the one PR in five that resisted compression (#525) is verifiably the one that carried the most novel content.

### 2. The Protected-Path Ledger and the `Founder-Read:` trailer [~2h agent to write the gate + ledger; the founder writes the list himself (30 min — this is a judgment call, not a delegation). Recurring: the trailer is one line per protected commit.]
A file `docs/protected-paths.md` listing every path where an agent may propose but never merge without the founder having read the literal bytes: `.github/workflows/**`, `wrangler.jsonc`, `apps/api/src/routes/billing.ts`, `apps/api/src/lib/stripe-tiers.ts`, `apps/api/migrations/**`, the auth/email/KV handlers in `src/worker.js`, `data/sourced-claims.json`, the `#voice-contract` block in `methods/index.html`, `.github/CODEOWNERS`, and anything that sends email or moves money. A single gate — `check-protected-paths.mjs`, wired to fail closed — rejects any commit touching those paths that lacks a `Founder-Read: <sha>` trailer. The ledger caps itself: if protected-path changes exceed ~40 files in a month, that is a signal to split the month's work, not to widen the list.

- Naive: Branch protection plus CODEOWNERS on sensitive directories, the standard protected-paths recommendation.
- Evolved: Branch protection is unenforceable when the protected party is the only account with merge rights; he can and does dismiss it. The evolved mechanism puts the receipt in git itself — a trailer naming the sha he read — so the claim 'a human read this' becomes an auditable artifact that survives a context reset, which is the only kind of memory this company has. Critically, the list is scoped by *irreversibility*, not by sensitivity: `billing.ts:174-175` charging a 5-seat Team $300 instead of $60 sat undetected under 40 green product gates because no rule said a money file gets different treatment from a copy file.

### 3. The Founder Diff Hour — a hard review budget that throttles merge volume [~3h agent to build the agenda generator and the budget gate. Recurring founder cost: 60 min/week, which is 25-30% of his stated capacity — deliberately expensive, because it is buying back the engineer's seat.]
A fixed weekly 60-minute calendared slot with a generated agenda produced by components 1 and 2: (a) every protected-path diff in full text, (b) every NOVEL singleton shape from the week's branches, (c) five randomly drawn MECHANICAL shapes as a spot check. The agenda is sized at 300 LOC/hour. Anything that does not fit does not merge — it waits for next week or gets split. `check-review-budget.mjs` computes the pending agenda size and fails the merge path when it exceeds the budget.

- Naive: 'Set aside time to review agent output' — the standard advice against comprehension rot.
- Evolved: That advice has been available to this founder for months and the measured compliance is one code commit in 33 days. The evolved version inverts the constraint: review capacity is treated as the scarce input and *merge volume is capped by it*, exactly as the audit's capacity ratchet (53 obligation-hours vs 13-26 available) says every other resource should be. This is the single most counter-cultural recommendation here — it deliberately slows the agent workforce down — and it is the only one that addresses the actual arithmetic. The alternative, which is the status quo, is that unreviewed output accumulates as liability until something like the 72 falsehoods on the flagship post gets called by a stranger.

### 4. Calibrated sampling with a published error rate — `scripts/sample-and-score.mjs` + `data/verification-calibration.json` [~6h agent for the sampler, the verifier prompt contract, and the JSON schema. Recurring: 20-30 founder-minutes/week for the 5 adjudications (fits inside the Diff Hour). Publishing surface: one page, ~2h.]
Weekly: draw a stratified random sample of 20 agent-authored changes that passed all gates (strata: published prose containing a number, code touching money/data, gates themselves, generated pages). A *write-denied* verifier session re-derives each claim from primary evidence and returns pass/fail with a citation. The founder personally adjudicates 5 of the 20. The output is an append-only `data/verification-calibration.json`: escaped-error rate per stratum with a Wilson interval, sample size, and adjudication agreement between founder and verifier. When any stratum's rate exceeds a threshold he sets, that stratum's changes move to full review until it recovers.

- Naive: Build an eval harness: judge model from a different family, pinned version, blind to the maker's reasoning, scoring the path not just the answer, run on every output.
- Evolved: A census judge is unaffordable and, worse, counterproductive here: `check-all` already runs 320 entries in 186 seconds with a 37.5% phantom-red rate, and adding a per-output judge would add noise to a signal channel the founder has already learned to discount. Sampling gives a *measured* number with an interval instead of an assumed one, at ~1/50th the cost. The second evolution is the one the source material misses entirely: **publish it**. This company's differentiator is falsifiable honesty — `no-llm-ci.sh` is already verifiable by a stranger in thirty seconds. A published, human-adjudicated error rate on its own agent output is simultaneously the review control and the strongest available marketing asset, and no competitor can copy it without becoming measurable themselves.

### 5. Untrusted-input quarantine — the read/write permission split [~4h agent for the gate and the schema contract; 30 min founder to approve the trust boundary list. Must land *before* the first scheduled session is pointed at the Issue queue.]
A written rule with a gate: any agent session or workflow that ingests text not authored by Don or a Muntin agent runs with **no repository write permission and no secrets**, and may emit only a fixed JSON schema (enum verdict + bounded fields + file:line pointers), never free prose. Applies to: reader field notes (`src/lib/submissions.js` → `src/worker.js:6495`), `/api/window/*` threads and `/admin/window/`, `/api/admin/submissions/*`, GitHub Issues on both public repos, fetched competitor pages, and external data feeds. A second, write-capable session acts on the schema and never sees the source prose. `check-untrusted-inputs.mjs` enumerates every workflow holding `contents: write` or a secret and fails if any of them also performs an outbound fetch or reads Issue/comment bodies.

- Naive: 'Sanitize untrusted inputs' and 'be careful with community skills that may carry prompt injection.'
- Evolved: Sanitization here is already implemented — and against the wrong threat model. `sanitizePlaintext` in `src/lib/submissions.js` escapes for HTML so the text is 'safe to substitute into HTML templates'; that does nothing about 400 words of reader-authored prose landing in a committed data file that an agent then reads as context. The evolved rule borrows the factory's write-permission split but applies it to *input trust* rather than to task type, which is the axis that matters when the repos are public. Two Muntin-specific facts force it: both repos are public, so GitHub Issues are world-writable, and the founder's stated next move is to point scheduled sessions at the Issue queue those four crons feed. Be precise about what is and is not live today: the competitor-claims `detail` field is bounded (check-competitor-claims.mjs:43,86,94) and is not currently exploitable; the field-note path and the Issue queue are.

### 6. Spend governor and blast-radius caps [~1h agent for the workflow cleanup; 15 founder-minutes in the console for the spend cap; the branch-permission rule is 3 lines in CLAUDE.md.]
Four limits, written in CLAUDE.md and enforced where enforceable: (a) a per-session wall-clock and turn cap; (b) an account-level daily spend cap set in the Anthropic console; (c) max 2 retries on any automated loop, with the second failure escalating to a human rather than retrying; (d) the one that actually matters — **no unattended or scheduled session holds write permission to `main`**; overnight work lands on a dated branch and the morning agenda item is 'what did the night produce.' Plus a concrete cleanup: delete `git checkout -- . 2>/dev/null || true` from cost-index-dispatch.yml:129, cost-index-refresh.yml:313 and cost-pressure-refresh.yml:152, replacing the staging allowlist with a path-scoped `git add -A` plus a denylist (this also retires the three-time-recurring staging bug the audit documents).

- Naive: 'Set per-run budgets, daily caps and max retries.' A dollar-denominated governor.
- Evolved: Dollar caps address the wrong failure. A pre-revenue company survives a $200 overnight burn; it does not survive an unattended loop force-pushing to `main` at 3am, or a `git checkout -- .` discarding a correct data refresh — which has already happened twice per the workflow's own comment block. So the governor is denominated in **blast radius** first and dollars second. The dollar cap is still worth ten minutes because there is currently *zero* of it anywhere: the grep across both repos returns one unrelated hit.

### 7. Comprehension probes — making the rot measurable, and gating expansion on the score [~3h agent for the question generator and the freeze gate. Recurring founder cost: 20 min/month to answer, plus whatever read-through a failed score demands — that cost is the point.]
Monthly, a write-denied session generates 10 questions answerable only by someone who has read the code, drawn from the subsystems that changed most that month. Examples of the right shape: 'what happens to the freshly-built `data/cost-index-picker.js` at cost-index-refresh.yml:313?'; 'what does `assembleLegs` return when `convertQuantity` yields null?'; 'which five builders are absent from wrangler.jsonc `build.command`?'. The founder answers cold, from memory, before opening anything. Score and per-subsystem breakdown append to a two-line-per-month file. **The gate:** any subsystem where he scores below 6/10 is frozen to new agent feature work until he does a read-through and re-scores.

- Naive: 'Stay engaged with the codebase' / 'keep forming your own opinion' — the source material's cognitive-surrender warning, which is a disposition, not a mechanism.
- Evolved: A disposition cannot fail loudly, so it degrades invisibly until a decision goes wrong — and the precursor is already on the record: PR #536 merged with three accepted reds, two of which the board admits were 'inferred from the diff, NOT reproduced.' The evolved version makes comprehension a falsifiable score with a consequence. And it solves a second problem sideways: this company has never retired anything (gates ~90 → 320 in 33 days, 1,368 pages, ~70 runbooks, nothing removed). Under this rule the only two ways to raise a subsystem's score are to read it or to delete it — which is the first retirement forcing-function the company has ever had.

### 8. The Never-Delegate list and its inverse, in CLAUDE.md [45 founder-minutes to write the five items (he must author these). ~1h agent to add the escalation-tag convention and a tally script.]
Under 15 lines in the one file that loads into every session. Never delegated: (a) what a published number *means*; (b) any first-time claim about the operator's own experience; (c) accepting a red; (d) retirement — what dies; (e) pricing and what the company charges for. Paired with an explicit 'decide, don't ask' list so agents stop escalating trivia. Every escalation an agent raises carries a one-line `DECISION-TYPE: a|b|c|d|e|new` tag, so escalation volume by type is countable — if type (c) 'accepting a red' fires more than twice a month, the gate suite is the defect, not the founder's discipline.

- Naive: Write an ADR series recording the decisions; keep a decisions log.
- Evolved: 26 ADRs already exist and the mechanism demonstrably does not hold: ADR-020 — deferring all revenue by twelve-plus months, the largest strategic act in company history — is 80 lines containing the words market, competitor, revenue and customer zero times, and no domain in a 38-agent audit flagged it. Separately, `check-src-sentinel.mjs` was designed by the founder himself, named 'rung 0' in docs/strategy/2026-07-28-frontier-north-star.md:165, and never reached the resume-here board — the memory layer lost the company's sharpest finding. Adding a 138th doc cannot fix that. The evolved version puts the five items in the only file with guaranteed universal load, keeps it short enough to survive the CLAUDE.md universal-applicability test, and — the real advance — makes escalations *countable by type*, converting 'is he still the engineer?' from a feeling into a monthly number.

## Advance
- **Review-surface compression: hash each file's diff with digits normalized, group by hash, and review *shapes* rather than files. Measured on this repo, agent PRs collapse 12-33x — PR #520 1,262 files → 53 shapes, #528 768 → 40, #526 1,359 → 105 with the top six shapes covering 961 files. It also discriminates: PR #525 refused to compress (1,399 → 432 shapes, 387 singletons) and is verifiably the PR carrying the most novel content. Shape count is therefore a free, sub-minute triage signal for 'how much human attention does this actually need.'**
  - Gap: The software-factory material measures cost per accepted change and splits agents by write permission, but has no answer for the case where a single accepted change is 1,673 files and 1.29M insertions. It assumes the reviewable unit is the PR. Here the reviewable unit is the patch shape, because the codebase's growth is injector-driven repetition across 1,368 near-identical pages. No source in the brief proposes changing the unit of review.
- **Comprehension as a scored quantity that gates expansion: a monthly cold-answer probe per subsystem, with a sub-6/10 score freezing that subsystem to new agent feature work until the founder reads it or deletes it.**
  - Gap: The four-bills material names comprehension rot as a risk to be aware of and gives it no control loop — no measurement, no threshold, no consequence. A disposition cannot fail loudly, so it degrades invisibly. Making it a score with a freeze also supplies the retirement forcing-function this company has never had (gates ~90 → 320 in 33 days; nothing ever removed), because the only two ways to raise the score are to read or to delete.
- **Publish the calibration. Sample 20 gate-passing agent changes weekly, have a write-denied verifier re-derive them, adjudicate 5 personally, and publish the escaped-error rate with a confidence interval at a public URL alongside `no-llm-ci.sh`.**
  - Gap: Eval engineering keeps the judge internal — a private quality-control instrument. For a company whose entire moat is stranger-verifiable honesty and whose most damaging live defect is a cite drawer promising verification that does not exist (blog/cost-index-2026-07/index.html:852), the measured reliability of its own review filter is not just a control, it is the most defensible marketing asset available and one a competitor cannot copy without becoming measurable. The source material never considers making the eval a public artifact.
- **Throttle merge volume by review capacity rather than maximizing agent throughput: a fixed weekly review budget in reviewed-LOC, with anything that does not fit blocked from merge rather than silently deferred.**
  - Gap: Every source treats agent throughput as the quantity to increase and review as an overhead to minimize. At Muntin the binding constraint runs the other way — 41,293 hand-authored lines in 33 days against 3-6 founder-hours a week is a 20-40x mismatch, so additional throughput produces only unreviewed liability. Naming review capacity as the scarce input, and capping production to it, is the inversion the material does not make. It is also the only recommendation here that deliberately slows the workforce down, which is why it is the one most likely to be resisted and most necessary.

## Rejected
- A judge-model eval harness run on every output (different model family, pinned version, blind to the maker's reasoning, path-scored). Sound at scale; unaffordable and counterproductive at 320 checks / 186 seconds / a 37.5% phantom-red rate on the founder's only local feedback loop. Adding a per-output judge adds noise to a channel he has already learned to discount. Sample instead of census — component 4.
- Adding gates of any kind as the primary response. This is now negative-value by default: 67.5% of hand-classified gates assert a shape, 56 of check-all's 320 entries are tautologies (the deploy runs a builder then asks the builder whether its own output matches), and zero of 129 storefront gates perform network I/O. The 2026-07-30 eval pass shipped six new gates and moved the close rate zero. Every component above is deliberately non-gate except the three that fail closed on irreversible paths.
- The five-layer memory stack (standards / project / fragile / handover / vocabulary). Muntin already runs seven overlapping memory layers: two CLAUDE.md files, a 1,488-line board, a 993-line archive, 26 ADRs, 194 docs markdown files, 16 planning docs and ~70 runbooks. The failure is not a missing layer — it is that `check-src-sentinel.mjs`, the founder's own sharpest finding, never travelled from docs/strategy/2026-07-28-frontier-north-star.md:165 into the resume-here board. A sixth store makes the retrieval problem worse, not better.
- Worktree-per-worker parallelism and the queue file as a fan-out engine. Adopt the write-permission split (which is about honest reporting) and reject the throughput half. Parallel workers multiply unreviewed surface against a founder who reviewed one commit's worth of code in 33 days; this is a review-capacity problem wearing a concurrency problem's clothes.
- 'Keep CLAUDE.md under 200 lines' as a headline lever. Worth doing — the product's is 213 and drifting, with situational content (recent-work threads, dated open items) that belongs behind an import — but it is a twenty-minute fix mis-sized as a strategy. The storefront's is 113 disciplined lines and the company still shipped 72 published falsehoods. Do it; do not call it the operating system.
- Every statistic in the supplied source material, repeated as fact: '19 of 20 PRs merge unreviewed', '97% error reduction', the '47x energy gap', '17,000+ skills audited with leaked credentials', and the '83.9% quality vs 32.3% faithfulness' figure the board already quoted back at itself on 2026-07-30. The mechanisms transfer and are used above; the numbers are secondhand and unsourced, and this company's own fact gate (docs/fact-check.md + data/sourced-claims.json) would reject any of them on a page. None appears as a premise in this design.
- Treating the four crons that open Issues (competitor-claims, flake-tracker, mutmut-nightly, cost-index-snapshot-watch) as an immediately exploitable injection vector. Checked and it is not — competitor-claims' `detail` field is bounded to `HTTP <status>` or a baseline-owned substring at scripts/check-competitor-claims.mjs:43, 86 and 94. The risk is prospective and becomes real the moment a scheduled session with write permission is pointed at that queue on a public repo. Said plainly rather than inflated, because inflating it here would be the same sin as the cite drawer at line 852.

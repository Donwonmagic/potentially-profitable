# The design system as an executable artifact — the manifest, the generator, the gate, and the migration path that reaches 1,327 pages

## Thesis
This company does not have a design system with a drift problem; it has a design system delivered by copy-paste and therefore no delivery mechanism at all. I measured it: 2,165 `<style>` blocks across the site resolve to only **151 distinct payloads**, and **14.01 MB of the site's 76.6 MB of HTML is a byte-identical duplicate of another block on another page**. One 32,332-byte block appears verbatim on 172 pages. That single number reframes everything — the site is not 1,327 bespoke designs drifting apart, it is roughly 151 stylesheets shipped by value instead of by reference, emitted by ~35 generator scripts. Which means the terrifying part (`inject-css-cache-bust.mjs` rewriting 786+ pages; I measure 1,234 pages currently carrying a busted core link) is terrifying for the wrong reason: not because the change is large, but because the change is *unaddressable* — there is no artifact to edit. Fix the addressing and a global design change becomes an edit to 151 files, or to 35 template literals, and everything else follows mechanically. So the sequencing is forced and it is not the sequencing a design studio wants: **mechanism first, pigment last.** Re-pigmenting tokens today would move almost nothing — 19,333 raw hexes already equal a token value (right colour, wrong mechanism) and 16,788 match no token at all. Second: the system's only durable form in this company is data plus a gate, because 1 of 108 agent transcripts loads a CLAUDE.md and `docs/design-system.md` is 489 lines of prose in a working set budgeted at 400 lines total. A design system that lives in a document is a design system that does not exist here. Third — the aesthetic call — the site's correct primitive is already built and is being used on one strip: `.lib-idx` at `assets/site.css:468-496`, a mono-header, hairline-ruled, tabular-figure register. Promote it to the site's spine primitive and delete the card family. A cost instrument read by a CPA should look like a register, not like three rounded cards in a row, which the frontier literature now names as the single most legible AI-authored tell — and this site is 80-84% agent-authored, so the default is exactly what gets built unless a gate forbids it. The one thing I will not do is add vocabulary. Every move below either deletes a value from the system or converts a value into an address.

## Proposal
## THE SPINE — a design system with four artifacts and no prose

The company's proven architecture is manifest → injector → gate. The design system becomes exactly that, with one rule: **the manifest is the only file a human authors.** The stylesheet is generated, the docs are generated, the agent-facing spec is generated, and the gate refuses anything outside the manifest.

### 1. The manifest — `data/design.spine.json`

Extends the already-shared `muntin.tokens.json` (do not fork it; add a sibling `spine` block and keep the md5 lock). It declares the *complete* legal vocabulary, and the count of each is the design decision:

- **Colour** — the existing 15-token cool spine, re-expressed in `oklch()` with a hex fallback per token. No new hues. `--teal:#2A50C8` becomes `oklch(43.6% 0.184 264)`/`#2A50C8`; the ramp steps are then arithmetic in L, not eyeballed. This is the *only* pigment change in the whole proposal and it lands last.
- **Type — 8 steps, named, no free values.** `--t-micro 11 / --t-fine 12.5 / --t-body 14.5 / --t-lead 16 / --t-sub 19 / --t-head 22 / --t-title clamp(28,4vw,40) / --t-display clamp(30,5vw,46)`. Chosen by *measured frequency*, not from a modular-scale generator: those eight sit on or within 0.5px of the site's nine most-used values (13/12.5/14/11/15/13.5/12/14.5/17). This collapses 240 values to 8 while moving almost nothing visually — the migration is a lookup table, and that is the point.
- **Weight — 3.** 500 / 600 / 700. Deletes 560, 540, 520, 420, 640, 800, 300 and the `!important`. Hierarchy comes from size and colour, per the Linear discipline; weight is not a variable.
- **Space — 6 steps + hairline.** 1 / 4 / 8 / 12 / 18 / 24 / 48. Covers 89% of measured occurrences. 70 → 7.
- **Radius — 3.** `--r-tight 6 / --r 10 / --r-pill 999`. I am changing `--r-lg` from the declared 8px to 10px because 10px is what the site actually renders 2,460 times and 8px renders 1,892; the token should describe the building, not the drawing. 35 → 3.
- **Motion — 2 curves, 3 durations, one law.** `--ease`, `--ease-out`, 180/420/900ms, transform+opacity only, and a required `prefers-reduced-motion` branch on any keyframe. Nothing new; this codifies the 43 branches already shipped.
- **Elevation — 2.** A hairline and one shadow. Not three. In a register-led layout the third tier has no job.

Every entry carries `{value, oklch, use, retires}` — `retires` naming the literal values it absorbs, so the migration table *is* the manifest.

### 2. The generators

- `scripts/build-spine-css.mjs (idem)` — emits the `:root` block and the dark flip at the top of `assets/site.css`, replacing the hand-maintained line 1 and folding in what `build-dark-mode.mjs` does today. Because both the light and dark roots come out of one pass, `build-css-shells.mjs` and `inject-css-cache-bust.mjs` each collapse from two runs to one: **85 build steps → 81.**
- `scripts/build-style-extract.mjs (idem)` — **the load-bearing one.** Walks every page, MD5s each `<style>` block, writes it once to `assets/s/<hash>.css`, replaces the block in place with `<link rel="stylesheet" href="/assets/s/<hash>.css">` at the identical position in `<head>`. 2,165 blocks → 151 files. **14.01 MB leaves the HTML.** Visual change: none by construction — same bytes, same cascade position. Content-addressed filenames make the cache-bust query string redundant for these files, so the busting problem that produced the 2026-05-04 FOUC bug simply stops existing for 88% of the site's CSS.
- `scripts/build-design-docs.mjs (idem)` — regenerates `docs/design-system.md` from the manifest. The doc becomes output, not input, and drops from 489 authored lines to 0 authored lines against the ADR-028 budget.

### 3. The agent interface — `scripts/lib/spine.mjs`

The single highest-leverage decision for a workforce of agent sessions. Mirror `scripts/lib/contract.mjs` exactly, because that pattern is already proven here and already printed by `.claude/hooks/session-start.sh`:

```
node scripts/lib/spine.mjs cost-index/broccoli/index.html
```

returns JSON: the legal vocabulary for that surface, the component it must use (`reg`, `held`, `viz-*`), a **worked example** of one correct row, the class of thing that is forbidden, and the exact gate command that will judge it. An agent gets the spec for the file it is touching, in the format it consumes, without loading a document. `session-start.sh` prints the eight-line core.

### 4. The gate — `scripts/check-on-spine.mjs`

Fails on any value outside the manifest: a font-size not in the 8, a weight not in the 3, a radius not in the 3, a hex not in the palette, a keyframe with no reduced-motion branch. Two properties make it different from `check-css-drift.mjs`, which failed:

- **It walks everything and carries an explicit skip list** with a reason per entry (the CLAUDE.md root-list rule, learned three times on 2026-07-28).
- **`--stdin`**: an agent pipes its generated fragment in and gets a verdict *before writing the file*. A wrong implementation fails at authoring time, not at deploy time. This is what "designed for agent execution" means concretely.

It ships UNWIRED with a dated registry entry and a violation count, per the standing rule; it gets wired the month its count reaches zero.

Companion: **`scripts/check-slop.mjs`** — the visual analogue of the product's `check-verboten-phrases.mjs`. Blocks the named AI-authored fingerprint: gradient orb behind a hero, `backdrop-filter` glass, a row of three identical icon cards, `@media(prefers-color-scheme:dark)` as the storefront default, bento grid. This is the only defense that survives 108 sessions where one loads a CLAUDE.md.

## THE AESTHETIC CALL — the register replaces the card

**The site's layout primitive becomes the ruled register, and the card family is deleted.**

`.lib-idx` (`assets/site.css:468-496`) is already the whole design: mono uppercase 10.5px/0.1em column heads in `--stone`; hairline `--line` between rows, `--line-dark` closing the block; `--font-mono` tabular dates; teal eyebrow for the section tag; a 5% teal `color-mix` on hover; a mobile branch that stacks to cards *only* below 640px. It reads like the cover of a reference work. It is used on one strip on `/learn/`. Promote it to `.reg`, apply it to every index on the site — library, glossary, cost-index, blog, sheets, tools — and delete the card grid.

Why this and not a card refresh: the reader who matters is a bookkeeper or a CPA deciding whether to recommend this, and the thing being sold is a closed month that foots. A register is the idiom they read fluently; density reads as competence in a numbers category and whitespace reads as marketing. It is also the only escape from the slop fingerprint that does not require inventing a look — the correct primitive is already built, already tokenised, already dark-mode-correct, and costs zero new CSS to adopt.

**The one component the system adds: `.held`.** A withheld cell keeps its slot, its tabular width, its baseline and its rules, and fills with a reason instead of a dash — because a hole reads as failure and a held position reads as a decision. Three parts, always: what is missing, why it blocks the number, and the one action that clears it. Rendered as `--stone` text at `--t-fine` in `--font-mono`, right-aligned to the same decimal column the number would have occupied, with a hairline underscore where the figure would sit. It is one CSS rule and one HTML pattern, it prints, and it is the visual form of the honesty contract. It is also the thing a card physically cannot do.

**Two retirements this forces.** The Golden Hour layer (`assets/site.css:3-47` + `assets/js/warmth.js`) is a warm radial-gradient orb behind a centered hero that leans warmer toward the reader's local evening. It is charming, it is well-built, and it is the first item on every published list of AI-authored design tells — changing the hue from indigo-purple to marigold-coral is a hue change, not an escape. On a page whose job is qualification by a CPA, time-of-day ambience is off-thesis. I am calling it: retire it. This is a genuine fork and the CSS comment calls it "sanctioned," so it deserves the founder's explicit yes-or-no rather than a silent deletion — but my recommendation is unambiguous. Second: the six display webfonts serving `library/menu-design-themes/*` go with the retired line.

**One thing I am deliberately declining.** No `@container`, no cross-document view transitions, no scroll-driven animation in this pass — every one is a new capability to maintain, and the storefront's problem is that it has too much vocabulary, not too little. Revisit after the gate is green.

## Risk
**The extraction is the whole bet, and its failure mode is a paint regression I cannot see from this container.** Moving 151 payloads from inline `<style>` to `<link rel="stylesheet">` preserves the bytes and the cascade position, so the *computed* styles are provably identical — but it introduces a network fetch on the critical path where there was none. This site has already shipped a FOUC bug once (documented in the header of `inject-css-cache-bust.mjs`, 2026-05-04), and there is no browser here to prove it has not recurred. The mitigation is real but partial: these files are shared across 78-266 pages each, so they are warm after the first navigation, and the existing lighthouse workflow measures the result. The honest limit is that step 2 must ship alone, with a rollback, and be verified on a device by the founder before anything else lands on top of it. If it regresses paint, the fallback is to extract only the payloads appearing on ≥20 pages and leave the long tail inline — which still removes ~13 of the 14 MB.

Three smaller risks, named. (1) **The type collapse is the most visible change and I chose it by frequency, not by ratio** — 240 values to 8 means roughly 232 values each shift by up to 0.5px, which is invisible per instance and could be visible in aggregate on a dense page. It needs a visual diff on ten representative pages, and this container cannot produce one. (2) **`check-on-spine.mjs` ships failing, as it must** — and the site's own history says an unwired gate with a large backlog is a gate that never gets wired. `check-css-drift.mjs` has sat UNWIRED with 505 issues since 2026-07-28. The only thing that makes this one different is that the violations live in 151 files and three generators rather than 1,327 pages, so the backlog is actually clearable; if that turns out to be wrong, this proposal has produced a second permanent debt tracker and nothing else. (3) **The register is a genuine aesthetic risk and it can read as cold.** The founder's stated failure mode is a site that feels "emotionless." I am arguing that a register is not cold but *authoritative* — the difference is the `.held` cell, which is the only warmth a cost instrument is entitled to, because it speaks to the operator about what it could not prove. If the founder reads the migrated indexes as austere rather than rigorous, the register was the wrong call and the recovery is expensive: the card family will already be deleted.

# Memory — engineering what this company forgets

## Thesis
Muntin's memory store is 87.8% log by line (1,307 of 1,489 board lines are episodic narration; 84 lines are facts, 98 are skills), and the 84 fact-lines are the part that has gone false. The board is not failing because nobody compacts it — it was compacted to 252 lines on 2026-07-17 and three more times since, and regrew to 1,488 lines within fourteen days; compaction as a chore loses to write pressure 3 out of 3 times measured. The retrieval failure that lost `check-src-sentinel.mjs` has an exact mechanism: the board cites 14 of 178 docs/*.md, because each session writes it from its own working memory rather than scanning the corpus — the north-star doc that named rung 0 contributed 22 of the 178 decisions in the compiled registry and is cited by the board zero times. That is the defect CLAUDE.md already names as its hardest-won rule — "a scanner is only as good as its root list" — applied to memory instead of pages, and never noticed. The one thing that works is the compiled layer Phase A built today (`prior-decisions.json`: 178 decisions, status MEASURED from the working tree, 22 conflicts surfaced, 43.3% ship rate) — and its builder is wired into no workflow, no check-all, no build.command, which is precisely how the Cost-Index snapshot went silently dormant for 42 days. So the design is not "write a better board": demote prose memory to a rendered VIEW of a probe-backed registry, applying this company's own `sourced-claims.json` fact-gate doctrine to its internal prose for the first time; make consolidation a corpus SCAN with a declared skip list; and make decay a CI budget gate that fails the deploy, because anything costing founder-hours gets paid at the measured rate of ~10%. Nothing is deleted — ADRs and slugs are final-forever and git holds the rest — but 1,223 board lines, 8 superseded handoff docs, 868 lines about a subsystem torn out on 2026-07-28, and the 2026-11-13 launch runbook leave the working set. The single highest-leverage item is C6: wire the four compiled-layer builders, because an unwired memory builder is the exact artifact this company has now shipped and lost three times.

## Design
### C1 — The probe-backed fact store: docs/memory/facts.jsonl + scripts/build-memory.mjs, extending the existing prior-decisions-registry.json mechanism rather than forking it [1 agent session. The probe engine already exists (scripts/build-prior-decisions.mjs, 23,850 bytes); this adds a second input file and a markdown renderer.]
Every durable fact gets one row: {id, claim, sourceFile, sourceLine, sourceSha, probe, probeType, expiresOn, theme}. probe reuses the four probe types already implemented in scripts/build-prior-decisions.mjs (files-matching, grep-min, grep-max, path-exists) so status is COMPUTED each run and never hand-written. Emits docs/memory/facts.json (measured) and docs/memory/state.md (rendered). The CAPTURE RULE is a rejection system: a candidate fact is refused unless it has (a) an executable probe, or (b) an expiresOn date within 90 days and a named owner. Anything that is neither is not a fact — it is a log entry, and log entries go in the git commit message, which already holds them.

- Naive: 'Store facts and skills, not logs' — rewrite the board into a facts section and a skills section, keeping prose.
- Evolved: Prose facts are exactly what rotted: five branch names, two builder counts, an ADR index missing 21 of 26 entries, a launch date its own file retracts 1,388 lines earlier. This company already invented the fix in its PUBLIC prose — sourced-claims.json registration, <!-- count:KEY --> sentinels re-derived by --check, and the doctrine that every number must be registered, cited, or labelled illustrative — and never once pointed it at prose agents read. The audit found 72 published falsehoods from static prose citing mutable data; the board has the identical disease with no gate at all. So: a fact at Muntin is a claim plus a probe. Nothing else is durable.

### C2 — scripts/check-memory-budget.mjs: decay as a fail-CI gate, not a chore [1 agent session, sequenced AFTER C7 (the retirement) or it reds on landing — the ordering constraint that killed rung 0.]
Hard caps checked in check-all: docs/memory/state.md <= 300 lines; storefront CLAUDE.md <= 5,000 tokens (measured chars/4, not lines — the current file is 113 lines and 4,749 tokens); any docs/memory/ section whose newest fact is >21 days old must be archived or carry a dated KEEP: reason in the style of check-positioning-drift's ALLOW list. Also caps the ratio: >=60% of state.md lines must be probe-backed. Ships with a --fix mode that moves over-age sections to docs/archive/ and rewrites the index, so clearing the red is one command rather than a judgement call.

- Naive: Adopt a forgetting policy: dedup, consolidate, decay on a cadence.
- Evolved: The policy already exists in the board's own header ('when a thread is fully shipped and superseded, summarize it to a line') and lost 3 out of 3 times over 14 days, ending at 5.9x its consolidated size. Measured founder capacity pays ~10% of maintenance-hours-due. A decay rule costing founder-hours will not be paid; one that reds the Cloudflare deploy will be. The --fix mode matters as much as the cap: CLAUDE.md forbids wiring a currently-failing gate, and a gate whose red costs an hour of judgement gets an ALLOW entry instead of a fix.

### C3 — scripts/harvest-corpus.mjs: consolidation as a SCAN with a declared root list [1 agent session. The harvest was already done once by hand today (178 rows) — this makes it repeatable and complete.]
Walks every docs/**/*.md in both repos plus the ADR directories and asserts each file is in exactly one of three states: HARVESTED (>=1 registry row naming it as sourceFile), SKIPPED (listed in an explicit SKIP array whose every entry states why it holds no decisions — voice canons, generated inventories, archives), or UNSEEN (fail). Records each harvested file's git blob SHA; a companion check fails when a harvested file's SHA moves without a re-harvest. Run at the end of any session that writes a doc under docs/.

- Naive: A consolidate stage: after each session, summarize what you learned into the store.
- Evolved: That IS today's protocol and it is per-session recall — it captured 14 of 178 docs and dropped the company's sharpest finding. The evolved version applies CLAUDE.md's own rule, learned three times on 2026-07-28 by shipping the bug first: declare roots, justify omissions, no third state. It is deliberately shaped like check-gate-coverage.mjs (wired / UNWIRED-with-reason / nothing else) because that gate demonstrably works — it forced the /course/ registry entry out when PR #530 deleted the script. The SHA-tracking half is the recompile trigger; without it the compiled layer ages invisibly the way the vendored snapshot did.

### C4 — Retire the board: docs/memory/state.md (<=300 lines, rendered) + a budgeted retrieval contract in CLAUDE.md [1 agent session, gated on C1 landing first (state.md needs something to render from).]
Four parts only, in read order: (1) OPEN — every fact with status never/partial and no closure, with its probe and evidence line, sorted by damage/minutes; (2) SKILLS — the ~98 runbook/gotcha lines, deduped (the four mutually-inconsistent idem-baseline entries collapse to one, the container-revert incident to one); (3) CONTRADICTIONS — C5's output; (4) POINTERS — the declared root list, so a session can see all 178 docs exist without reading them. CLAUDE.md's Continuity section is replaced by an ordered budgeted read: docs/memory/state.md (<=4K tok) -> facts.json OPEN rows (<=3K tok) -> named ADRs on demand. The six stacked CURRENT STATE blocks are gone; there is one state and it is generated.

- Naive: Keep a resume-here board; keep it tight; put full history in an archive.
- Evolved: That is verbatim what the 2026-07-16 consolidation did, and board-archive.md is its 993-line residue — the archive precedent exists and did not bound growth. Three things change. state.md is GENERATED from facts.jsonl, so a session cannot append prose; the only write path is a registry row carrying a probe. There is exactly one CURRENT STATE — six sections each headed CURRENT STATE is not a board, it is a stack, and it is why board:1446 still asserts a launch date board:58 retired. And the read is BUDGETED: today the protocol spends 45,100 tokens to deliver 0 registry-addressable decisions, and no budget was ever stated.

### C5 — scripts/check-memory-contradictions.mjs: reconcile with probe arbitration, three buckets not two [1 agent session.]
Detects contradictions across CLAUDE.md (both repos), docs/memory/facts.jsonl and the ADR set, then sorts each into: (A) PROBE-DECIDED — both sides make the same claim, one side's probe passes against the working tree and the other fails; the failing side is auto-demoted with a dated stamp and logged, no human touched. (B) PROBE-MUTE — neither side is probeable (a strategy call, a positioning judgement); goes to a queue in state.md hard-limited to 7 open entries, gate WARNS. (C) PROBE-CONFLICT — both probes pass and the claims are still opposite; fail CI, because the working tree itself is inconsistent. Never merges prose. Seeded with the 22 conflicts prior-decisions-summary.json already found.

- Naive: Never auto-merge contradictions; surface them and let a human decide.
- Evolved: Correct in principle and unaffordable here as stated. Measured: ~53 obligation-hours/month against 13-26 available, ~10% of maintenance-hours paid, 24 of 60 days producing nothing. A queue requiring a human decision per contradiction never drains — which is why board:1446's launch date has contradicted its own file for eight days. The evolved rule keeps the real invariant (prose is never silently merged) while routing to the human only what the working tree cannot settle, capped at 7. Bucket A is not a weakening: demote-only against a passing probe is exactly the monotone-downward semantics the founder specified at north-star:165 — 'the gate may only demote — stamp as-of, freeze the citation, or flag superseded. Never restate upward. Never author prose.'

### C6 — Wire the compiled layer, in the same commit it is written [1 agent session. Highest leverage of the eight; do it first or accept that the rest rots.]
Add build-prior-decisions, build-surface-inventory, build-link-graph, build-content-intent, build-memory and harvest-corpus to a single .github/workflows/memory-refresh.yml (weekly + on push to docs/), register each in check-idem-coverage.mjs's MANUAL registry with who runs it and when it drifts, and extend check-gate-coverage.mjs to enumerate build-*.mjs exposing a --check mode — closing the structural hole where a builder with an unrun --check is invisible to BOTH meta-gates. Move the three multi-megabyte inventories out of data/ (the published-dataset directory, 8.6MB committed) into docs/memory/inventory/, where internal memory cannot be confused with public data.

- Naive: Build the compiled layer (raw documents are source code; the wiki is the compiled product). Compile once, query forever.
- Evolved: The compiled layer was built today and is wired nowhere — no workflow, no check-all, no build.command, no MANUAL registry. Not hypothetical: it is bit-for-bit the failure that left apps/api/src/data/cost-index-snapshot.json 42 days stale past a 30-day resolver cliff, silently killing the ADR-009 market prior in production. 'Compile once, query forever' assumes raw stops moving; here raw grew ~88 board-lines/day. And the meta-gate hole is why nobody would notice: check-gate-coverage sees only check-*.mjs, check-idem-coverage sees only builders already inside check-all, so a memory builder falls between them exactly as 33 other builders already do. THIS component is what makes C1-C5 durable rather than finding #50.

### C7 — The retirement execution: ARCHIVE, never DELETE [1-2 agent sessions. Mechanical; the judgement lives in the harvest, which C3 already did.]
One session, one PR, executed only AFTER C3's harvest has captured each file's decisions into the registry (the registry keeps a live pointer, so the audit trail survives the move). Move to docs/archive/<yyyy-mm>/ with a one-line index entry each. BOARD: lines 133-1355, the four superseded CURRENT STATE blocks plus the closed honesty-spine thread (1,223 lines; open items extracted to facts.jsonl first), and board-archive.md itself (993 lines, 35,166 tok, currently inside docs/handoff/ beside live memory and inside CLAUDE.md's read path). RETIRED-SUBSYSTEM DOCS: docs/course-instructional-audit.md (540) + docs/course-audio-runbook.md (328) — 868 lines about a subsystem torn out 2026-07-28. SUPERSEDED DESIGN PROGRAM: reinvention-master-plan.md, site-reinvention-blueprint.md, redesign-execution-plan.md, redesign-v3-system.md, redesign-flagship-prototype.html, demo-redesign-plan.md, warmth-cohesion-plan.md, bolder-launch-session-2026-07-02.md (v3 shipped; the audit separately confirms the 'two design languages' fork these describe is CLOSED — the token spine is byte-identical and hash-locked across both repos). PLANS: the 4 with zero inbound references (ledger-demo-transform, muntin-cost-convergence, muntin-cost-history, open-data-explore-surfaces-plan) plus muntin-ledger-launch.md (superseded by ADR-020). PRODUCT RUNBOOKS: launch-plan-2026-11-13.md (the date ADR-020 retired), this-evening.md, ship-friday.md, founder-todos.md, phase-1a/1b/1c/1d-*.md (7 files); the 19 runbooks absent from runbooks/INDEX.md get indexed-or-archived. TODAY'S AUDIT ARTIFACTS: the 8 lens files and 10 greats files are harvested into the registry and archived in the same commit, so they cannot become audit artifact #9 and #10. DELETE list: empty.

- Naive: Prune the memory store: delete what has served its purpose.
- Evolved: Deletion is unavailable on the company's own terms (ADRs are decisions of record, slugs final-forever) and would be the wrong lever anyway — the cost is not disk, it is the read budget and the false-fact surface. Two Muntin-specific constraints shape it. ORDERING: archiving before harvesting destroys the audit trail — site-reinvention-blueprint.md alone contributed 14 registry rows, four with status 'never', real open work that would vanish. And ARCHIVE MUST MEAN OUT OF THE READ PATH, which board-archive.md currently is not: it lives in docs/handoff/ and CLAUDE.md points a fresh session there. Archive here is defined as 'retrievable by registry pointer, invisible to the retrieval contract' — not 'a different filename in the same folder'.

### C8 — The adherence check, but only if its output is a diff [1 agent session per run, but only after C4 (there must be a stable rule set to review against).]
After a real working session, a second session reads the transcript against docs/memory/state.md and both CLAUDE.md files rule-by-rule and emits ONE artifact: a patch. Rules followed -> no output. Rules ignored -> either a diff deleting the rule (it does not carry) or a diff adding a probe that would have caught the miss. Rules followed inconsistently -> a diff resolving the ambiguity. The session is forbidden from producing a findings list. Run quarterly, or after any CLAUDE.md edit over 20 lines.

- Naive: Verify adherence rather than hoping: run a real session, then have a second session review the transcript rule-by-rule for what was followed, ignored, or followed inconsistently.
- Evolved: The mechanism is right and the OUTPUT FORMAT is what kills it here. Measured close rate on audit findings is 26%, with zero closures in company history from anyone working a list — 14 of 49 were fixed inside the finding session and the other 10 closed incidentally. A transcript review that emits a report becomes the ninth unworked artifact. Constraining output to a patch collapses find-and-fix into one session, the only pattern that has ever closed anything here. It also serves the emphasis-marker test directly: storefront CLAUDE.md carries 61 bold-emphasis spans across 4,749 tokens with zero @path imports, so nothing is marked and everything is — a diff is the only honest way to learn which of the 61 a session actually obeyed.

## Advance
- **A fact at Muntin is a claim plus a probe; prose without a probe is a log entry with a decay rate. The memory-engineering literature says store facts, not logs — it does not say how a stored fact stays true, and it implicitly assumes facts are stable. Here they are not: the store's fact-lines are 5.6% of its volume and roughly half are currently false. The fix is not a discipline, it is a format — and this company already built the machinery (sourced-claims.json registration, count-sentinels, --check idempotency) and pointed it exclusively at prose readers see, never at prose agents read.**
  - Gap: The source material has no answer to 'a stored fact went stale — now what.' It offers decay by age, which cannot distinguish a 30-day-old fact that is still true from a 3-day-old one already false. board:144 ('check-all is 327 of 327') was true the day it was written and false eight days later; age would have kept it, a probe would have caught it in one CI run.
- **Probe-arbitrated reconciliation: three buckets, not two, with a hard cap on the human bucket. 'Never auto-merge contradictions; surface them, a human decides' is correct about prose and wrong about capacity. The evolved rule auto-DEMOTES (never promotes, never authors) any contradiction where exactly one side's probe passes against the working tree, routes only the genuinely unprobeable to a human, and caps that queue at 7 — because a queue with no cap is a queue with no priority.**
  - Gap: The source material assumes a human decision-maker with slack. Muntin has ~53 obligation-hours/month against 13-26 available and pays ~10% of them. An uncapped human contradiction queue here is measurably a queue that never drains: board:1446 has contradicted board:58 for eight days inside the single file a human is instructed to read first. The demote-only semantics are borrowed from the founder's own check-src-sentinel spec, so the safety argument is already made and already accepted here.
- **Decay must fail the deploy, or it does not happen. The source material frames forgetting as a policy adopted before the store grows. Muntin ran that experiment: the policy was written into the board's own header, four compactions were performed, and the store still grew 5.9x in fourteen days. The evolved form is a budget gate with a --fix mode — a hard line cap, a hard token cap, an age rule with a dated-reason escape hatch, and one command that clears the red.**
  - Gap: No source in the pack distinguishes a policy from an enforced policy or prices the difference. Muntin measures it: policy-as-chore lost 3/3 in 14 days, while the analogous enforced version (check-idem-coverage's MANUAL registry) forced the /course/ entries out on 2026-07-29 because the gate demanded it. Same company, same month, opposite outcomes — the only difference is whether it reds the deploy.
- **The Karpathy raw-to-wiki pattern needs a recompile trigger, and the trigger must be a source blob SHA, not a date. 'Compile once, query the compiled layer forever' assumes raw documents settle. Here they grow ~88 board-lines/day across 178 unevenly-churning docs. Every harvested row therefore carries the git blob SHA of the file it came from, and a gate fails when a harvested source has moved without a re-harvest — the same anti-drift construction as check-cost-index-snapshot-freshness.mjs, which parses its threshold out of the consumer so gate and consumer cannot disagree.**
  - Gap: The wiki pattern has no staleness contract, so a compiled layer degrades invisibly and looks healthiest right before it is most wrong — exactly the 42-day dormant-snapshot failure, and exactly the risk facing the registry compiled hours ago and wired nowhere. A date-based trigger would not help: the correct recompile interval is 'whenever a source moved', which is cheap to measure and free to check.

## Rejected
- The five-tier memory stack (standards / project / fragile / handover / vocabulary). Five stores where one is already unmaintained and 87.8% waste. Every added store multiplies the reconcile surface — the store already contradicts itself across four sections of a SINGLE file, and CLAUDE.md contradicts it on builder counts. Muntin gets two tiers: probe-backed facts (machine-owned) and skills (human-owned, <=100 lines). Nothing else.
- Vector/embedding retrieval or semantic memory search. 178 documents and 738K tokens is a grep-and-index problem, not a retrieval-model problem. The measured failure was never 'the right doc could not be found' — it was that nothing ever looked. harvest-corpus.mjs with a declared root list solves the actual defect for one session and zero infrastructure.
- Storing session transcripts or episodic traces for later mining. That is precisely what the board is, and it is the 1,307-line waste. Git already holds every commit message, diff and SHA; the board's shipped-work narration is a lossy second copy of data git stores losslessly. 'Mine real traces rather than inventing tests' is right for evals and wrong for memory: mine the WORKING TREE, the only trace that is still true.
- The two-session CLAUDE.md adherence review as specified — as a review. The mechanism transfers; the artifact does not. This company has produced 8 prior audit artifacts, 49 findings, a 26% close rate and zero closures from anyone working a list, and today added an audit plus 18 lens/greats analyses. A ninth report is a negative-value deliverable. Accepted only in C8's form, where the session may emit a patch and is forbidden from emitting a list.
- 'Judge memory by decision-relevant information per token' as a tracked metric. Directionally right, unmeasurable without a human grading pass, and the grading pass costs more than the compaction it would justify. Replaced by a proxy a gate computes in milliseconds: percentage of state.md lines that are probe-backed, floored at 60%.
- Any DELETE at all. ADRs are decisions of record, slugs are final-forever, and the fact gate's premise is that the record survives the claim. Archive-with-registry-pointer gives every benefit deletion would (out of the read path, out of the contradiction surface, out of the token budget) at zero cost, because git stores the bytes whether or not the working set does. The one thing that must NOT be archived is anything with an open registry row — which is why C7 is ordered strictly after C3.
- 'Add a forgetting policy before the store grows.' Not wrong — unavailable. The store is 2,481 board lines plus 178 docs plus 76 runbooks and passed that point weeks ago. The transferable half is what it implies about sequencing, and the actionable consequence is C7 before C2: retire first, then cap, because CLAUDE.md's own rule forbids wiring a currently-failing gate — and splitting exactly that bundle is what killed rung 0 ten days ago.

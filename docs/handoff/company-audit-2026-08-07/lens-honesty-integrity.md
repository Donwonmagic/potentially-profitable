## Why count: and repro: are enforced and src: is not — and the gate that closes it
The two enforced sentinels share a shape the `src:` convention lacks: a named builder owns the value, and `--check` re-derives it.

`<!-- count:KEY -->N<!-- /count -->`: `data/site-counts.json` is the declared source of truth, `inject-site-counts.mjs` stamps, and two gates guard it — `check-counts-coherence.mjs` (which also chases un-sentineled count claims in meta/og text) and `check-count-sentinel-escape.mjs`.

`<!-- repro:value -->...<!-- /repro -->` is the closer template. `scripts/build-cost-index-reproduce.mjs` is ~90 lines: it reads `cost-index/ribeye/series.json`, takes the latest observation, stamps EN+ES, and its header states the design goal outright — "If the published value moves, this re-stamps it; --check fails if the page drifts from the feed, so the worked example stays true by construction." It is wired at `check-all.mjs:678-679` as both a self-test and a `--check`. That is exactly the mechanism the July dispatch needed and did not get.

`src:` has none of it. It is a freeform comment with no parser, no builder, no `--check`, and — because it names files rather than pointers — nothing resolvable. The concrete fix, in the order it should be built:

STEP 1 (the freeze, ~1.5 h). `build-cost-index-dispatch.mjs` already writes `cost-index/week-<asOf>.json` and "never rewrites an existing frozen snapshot." Extend that writer to emit a sibling `cost-index/edition-<asOf>-context.json` capturing the seven artifacts' summary surfaces: `lockfloat.counts` + per-item `{bucket, halfWidthPct, coverageLo, level, nTested}`, `seasonality.summary` + `params` + each panel item's `months['MM'].medianCents`, `revisions.{count, byType, medianAbsDelta, p90AbsDelta, maxRevision}`, the whole calibration report, the backtest `verdict` + `horizonCone` + `seasonalTermStructure`, and `outlook` + per-item `pressure.direction`. This is the spine's own doctrine — "one entry per asOf; never overwrite" — applied to the six files it forgot.

STEP 2 (the gate, ~3 h) — `scripts/check-src-sentinel.mjs`. Promote the annotation to `<!-- src: edition-2026-07-06-context.json#/lockfloat/counts/withhold -->73<!-- /src -->`. Parse: (file, RFC-6901 JSON pointer, rendered value). Resolve the file RELATIVE TO THE PAGE'S OWN EDITION, never to `data/`. Compare with a declared tolerance (±0.05pp for percentages, exact for counts). Failure modes, in the founder's own words from `docs/strategy/2026-07-28-frontier-north-star.md:165`: "on disagreement the gate may only demote — stamp as-of, freeze the citation, or flag superseded. Never restate upward. Never author prose." Three exit paths: pointer unresolvable -> fail; value disagrees -> fail; annotation names a file under `data/` (i.e. a live, mutable artifact) -> fail, because that is the bug class itself. Add a dated LEGACY registry for un-migrated annotations, following `check-gate-coverage.mjs`'s doctrine that "there is no third state." Wire it into `check-all.mjs` in the same commit, and — per this repo's own hard-won rule — only after the violations are fixed, or the deploy reds for everyone.

STEP 3 (root list, ~20 min). The scanner walks EVERY `.html` in both repos with an explicit skip list, not just `blog/`. The CLAUDE.md rule was learned three times in one day: "a script that scans the site walks everything and carries an explicit skip list, where every entry says why it is not reader-facing prose." Today the pattern happens to live in one file; a narrow scanner guarantees the next one is invisible.

## The cheapest correct repair is not to restate 72 numbers — it is to stamp them
The instinct is to hand-correct each figure against today's files. DON'T. That is hours of work, it will be wrong again on the next refresh, and it destroys the of-record property the publication exists for: an edition is supposed to be a DATED READ, not a living document.

The post already knows how to do this correctly. Its lede (L502) reads "READ AS OF JULY 6: the 16-staple wholesale basket sits −5.0%", and the frozen snapshot backs it. The 72 broken claims are broken because they are written in the TIMELESS PRESENT — "The classifier certifies 15 locks," "39 of 100 tracked ingredients carry enough distinct years," "The revision ledger holds 2,080 entries." Add the as-of and every one becomes a true historical statement with NO NUMBER TOUCHED:

- L821 -> "On the 2026-07-06 run, the classifier certified 15 locks..."
- L763/L818/L814 -> "As of the 2026-07-06 seasonality build, 39 of 100..."
- L851 -> "July's grades, from the 2026-07-06 calibration run..."
- L636/L891 -> "...a ledger that held 2,080 entries at that print."
- L524/L847 -> "On the 2026-07-06 outlook, the read was mixed..."
- L629/L757 -> "The 2026-06-08 pressure layer read romaine building..." (L754 already stamps this correctly — copy its pattern.)

That is one editing pass over seven paragraphs, ~45 minutes, and it converts 72 live falsehoods into 72 correctly-dated historical statements.

THREE THINGS AS-OF STAMPING DOES NOT FIX, each needing its own edit. (a) L852's drawer — "re-checked in CI. Every number in this section traces to one of them" is false at any date; delete the CI clause and repoint the drawer at the frozen edition, or the fix leaves the worst sentence standing. L818 needs the same treatment. (b) The FAQPage JSON-LD at lines 105–108 — crawlers and answer engines lift the `text` field without surrounding context, so the as-of must go INSIDE the answer string, not in the surrounding HTML. (c) The two inverted forward reads (outlook `mixed/−0.145` -> `building/+0.055`; `seasonalBeatsPersistence` true -> false) — a date stamp makes these honest, but a reader arriving today gets a directional read the company's own current file contradicts. Consider a one-line dated superseded note pointing at the current outlook.

Then build Step 1 (the freeze) so the NEXT edition is immune, and Step 2 (the gate) so this is the last time it can happen silently. Sequencing matters: FREEZE BEFORE GATE, because a gate wired against `data/` today would red the deploy on 61 annotations with no frozen target to point them at.

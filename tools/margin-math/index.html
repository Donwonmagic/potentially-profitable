How we protect the numbers you type

Eight claims. Each one is verifiable in your own browser in under a minute. If any of them turn out to be wrong, we want you to find out first — open every "Inspect this" and check us.

1

Your numbers never leave this page.

No fetch(), XMLHttpRequest, or form submission fires when you type a financial number. The calculator math runs entirely in your browser.

Inspect this
Open DevTools (Cmd+Opt+I / Ctrl+Shift+I) → Network tab. Type a number into the calculator above. The request list should not grow. If it does, that's a bug — tell us.
2

There's no server to store them on.

The only endpoint this page uses is GET /tools/margin-math/. No /api/margin-math-save, no /api/calculate, no logger. The Worker can't hear you.

Inspect this
From a terminal: curl -X POST https://muntin.digital/tools/margin-math/. Response: 405 Method Not Allowed (or similar) — there's nothing listening for POSTs.
3

Analytics sees only buckets, never numbers.

Plausible receives properties from a short, fixed list of enumerated values. A \$25 ticket becomes 25-39. A 30% food cost becomes 28-32. Your raw numbers are never a value on any event.

Inspect this
DevTools → Network → filter plausible. Interact with the calculator. When the event fires, look at its payload. Values like ticket_bucket: "25-39" — never ticket: 25.00.
4

No cookies, no localStorage, no sessionStorage — for your inputs.

Your typed numbers live only in JavaScript variables, which disappear when you close the tab. There's no persistent state for the calculator.

Inspect this
DevTools → Application → Storage. Use the calculator. Check Cookies, Local Storage, Session Storage, IndexedDB for this origin — the panels stay empty of any financial value.
5

No third-party scripts touch the inputs.

This page loads exactly two JavaScript files: site-wide site.js (nav + language switch) and tool-specific margin-math.js (the math). Plus one analytics script (Plausible) that receives the bucket values. Nothing else.

Inspect this
DevTools → Network → filter JS. Reload. You should see plausible.io/js/…, site.js, and margin-math.js. No Google Tag Manager, no Meta Pixel, no chat widget, no session replay.
6

Shareable URLs keep numbers out of the server logs.

When we ship "Save this scenario" (later phase), the numbers will be encoded in the URL fragment — after the #. Per HTTP specification, browsers never send fragments to servers. The permalink works; the server never sees its contents.

Inspect this
Links like …/margin-math/#calc=delivery&t=25&f=30 hydrate the state locally. We also set <meta name="referrer" content="no-referrer"> on this page — so outbound clicks can't leak the fragment to a third party via Referer.
7

The source is readable.

No build step, no minification, no framework. The math module is plain JavaScript — you can read every line.

Inspect this
Right-click this page → View Page Source. Or open /tools/margin-math/margin-math.js directly. Search for function mmCalcDeliveryBreakeven — that's the whole math, in the open.
8

Nothing persists beyond this tab.

Close the tab, reopen the tool: every calculator resets to default. There's no account, no saved history, no "welcome back."

Inspect this
Change every slider and input. Close the tab. Reopen /tools/margin-math/. Everything is back to its starting value.

How to check if any tool is safe

Five tests you can run on any free financial tool you encounter — before you type a single real number into it. We score ourselves alongside a typical lead-generation free tool so the difference is concrete, not rhetorical.

The test Margin Math Typical free tool
1. Does typing a number trigger a network request?Open DevTools → Network. Type. No requests fire. Every keystroke POSTs to a server.
2. Is the privacy claim at the point of input?Not buried in a policy page. "Stays in your browser" badge on every card, full 8-step panel in-page. Privacy Policy link in footer only; implicit consent on submit.
3. Is there an account / newsletter / cookie gate?Anything demanding "accept all" before you can use the tool. Nothing — no gate, no popup, no cookie banner. "Enter your email to see your results."
4. Any third-party analytics, session replay, marketing scripts?DevTools → Network → filter JS. Privacy-first Plausible only; bucket props (never raw values). Google Analytics, Meta Pixel, HubSpot, session replay — stacked.
5. Is the source code readable?Right-click → View Source. Unminified, under ~500 lines, every math function named. Minified SaaS bundle; math hidden inside a framework dashboard.

Apply the same five tests to any calculator, estimator, or "free audit" you encounter — especially one asking for revenue, margin, food cost, or labor numbers. A tool that silently POSTs your inputs is storing them. A tool with no in-page privacy claim is dodging the question. You're allowed to walk away.
